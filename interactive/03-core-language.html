Core Language and Modern C++

The ideas that separate "I know C++ syntax" from "I write modern C++": RAII, move semantics, smart pointers, lambdas, exceptions and casts, plus a tour of what C++11 to C++20 added. You should be comfortable with Basics and OOP first.

RAII: the central idea

Resource Acquisition Is Initialization. Tie the lifetime of a resource (heap memory, file, lock, socket) to the lifetime of an object. Acquire it in the constructor, release it in the destructor. Since destructors run automatically at the end of scope, even when an exception is thrown, the resource can never leak.

Watch what happens when something throws in the middle:

You have already been using RAII: std::vector frees its memory, std::unique_ptr deletes its object, std::lock_guard unlocks its mutex, std::fstream closes its file. The rule: never manage a resource with a bare new/delete, lock()/unlock() or fopen/fclose pair in your own code. Wrap it.

Interview angle"What is RAII and why is it important?" It binds resource lifetime to object lifetime so cleanup is automatic and exception-safe. It replaces try/finally (which C++ does not have) and is the reason C++ needs no garbage collector.

Lvalues, rvalues and references

An lvalue is an object with a name and an address you can take (x, v[0]). An rvalue is a temporary with no name (5, a + b, a function's returned value). Rvalues are about to disappear, so their guts are safe to steal.

Move semantics

Copying a std::vector with a million elements allocates and copies a million elements. If the source is a temporary that is about to be destroyed anyway, that is wasteful. A move just steals the internal pointer and leaves the source empty.

  • std::move(x) does not move anything. It is only a cast to an rvalue reference, a signal that says "you may steal from this". The actual stealing happens in the move constructor or move assignment that gets selected.
  • A moved-from object is valid but unspecified. You may destroy it or assign a new value to it. Do not read its value.
  • If your type holds a raw resource, write the Rule of Five. Mark the move operations noexcept: std::vector only moves elements during reallocation if the move cannot throw, otherwise it falls back to copying.
Do not write return std::move(local);Returning a local by value already allows the compiler to elide the copy entirely (RVO/NRVO) or move it automatically. Adding std::move blocks the elision and makes things slower.

Smart pointers

Smart pointers are RAII wrappers around new/delete in <memory>. They make ownership explicit in the type.

Reference cycles and weak_ptr

If A holds a shared_ptr<B> and B holds a shared_ptr<A>, each keeps the other's count above zero forever: neither is ever destroyed, a leak that RAII cannot fix. Make one direction (usually the "back-pointer" or parent link) a weak_ptr.

Ownership rules of thumb

Default to unique_ptr (or better, a plain value member). Use shared_ptr only when ownership is truly shared. A raw pointer or a reference means "I use it, I do not own it". Pass a smart pointer by value only to transfer or share ownership; otherwise pass T& or T*.

Interview angle"Why make_unique/make_shared instead of new?" No naked new (exception safety, no leak if another argument throws), less typing, and make_shared does a single allocation instead of two.

auto traps

auto x = {1, 2, 3}; deduces std::initializer_list<int>, not a vector. auto drops references and const: auto y = v[0]; copies the element; write auto& y or const auto& y to avoid the copy. Likewise for (auto [k, v] : map) copies every pair; use const auto&.

Lambdas

A lambda is an unnamed function object you write in place. The compiler turns it into a small class whose operator() holds the body and whose members hold the captures.

PredictCapture by value vs by reference

byVal took a snapshot of x (1) when it was created. byRef sees the variable itself, so it reads the new value 2. A by-value capture is const inside the lambda unless you add mutable.

Dangling capturesA lambda that captures a local by reference and then outlives it (returned from the function, or run later on another thread) reads destroyed memory. When a lambda escapes its scope, capture by value.

std::function can store any callable of a given signature, but it type-erases and may allocate. Prefer auto for a local lambda and a template parameter for a function that accepts one.

Exceptions and exception safety

  • Throw by value, catch by const&. Catching by value slices the exception object.
  • When a throw happens, the runtime performs stack unwinding: it leaves scopes one by one, running destructors, until a matching catch is found. This is why RAII makes code exception-safe.
  • A destructor must never throw. If it throws during unwinding, std::terminate is called and the program dies. Destructors are implicitly noexcept.
  • noexcept promises a function will not throw. It enables optimisations (such as moves in vector) and if the promise is broken the program terminates.
  • Use exceptions for exceptional failure, not routine control flow, and not on real-time hot paths where the throw cost is unacceptable.

Casts and type conversion

C++ replaces the single dangerous C cast (T)x with four named casts, each saying exactly what you intend and easy to search for.

RuleIf you need many casts, the design is probably wrong. Prefer virtual functions to dynamic_cast chains, and never use a C-style cast in new code.

const, constexpr and static

  • const: the value cannot change after initialization (checked at compile time). Use it everywhere you can.
  • constexpr: the value (or function result) can be computed at compile time, so it costs nothing at runtime and can be used in array sizes and template arguments.

The keyword static means three different things depending on where it appears:

Interview cheat sheet

What does std::move actually do?

Nothing at runtime: it is an unconditional cast to an rvalue reference. It enables the move constructor or move assignment to be chosen. The moved-from object stays valid but unspecified.

unique_ptr vs shared_ptr vs weak_ptr?

unique_ptr: sole owner, move-only, zero overhead. shared_ptr: reference-counted shared ownership with a control block and atomic count. weak_ptr: non-owning observer used to break cycles and to check whether a shared object is still alive (lock()).

Is shared_ptr thread-safe?

The reference count is atomic, so copying and destroying shared_ptrs from different threads is safe. The pointed-to object is not protected: concurrent access to it still needs synchronization. Concurrently modifying the same shared_ptr variable is also a race.

What is copy elision / RVO?

The compiler constructs a returned object directly in the caller's storage, skipping the copy or move. In C++17 it is guaranteed when returning a temporary (prvalue). Do not write return std::move(local): it prevents it.

What is stack unwinding?

When an exception propagates, the runtime exits scopes up the call stack, calling the destructors of all fully constructed locals until a handler is found. It is what makes RAII exception-safe.

Why should destructors not throw?

Destructors run during unwinding. If one throws while another exception is active, std::terminate is called. Destructors are noexcept by default; catch and handle errors inside them.

When would you use dynamic_cast?

For a checked downcast from a polymorphic base to a derived type when you cannot express the need through a virtual function. It returns null (pointers) or throws bad_cast (references) on failure. Frequent use suggests a design problem.

Difference between const and constexpr?

const means read-only after initialization (the value may be determined at runtime). constexpr means the value or function can be evaluated at compile time and usable in constant expressions.
