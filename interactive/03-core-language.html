Core Language and Modern C++

What separates "I know C++ syntax" from "I write modern C++": RAII, move semantics, smart pointers, lambdas, exceptions, casts, and C++11 to 20 features. Assumes Basics and OOP.

RAII: the central idea

RAII: tie a resource (memory, file, lock, socket) to an object. Acquire in the constructor, release in the destructor. Destructors run even when an exception is thrown, so nothing leaks.

Watch a throw in the middle:

vector, unique_ptr, lock_guard, fstream are all RAII. Never manage a resource with a bare new/delete, lock()/unlock() or fopen/fclose: wrap it.

Interview angleRAII binds resource lifetime to object lifetime: automatic, exception-safe cleanup. It replaces try/finally and removes the need for a garbage collector.

Lvalues, rvalues and references

An lvalue has a name and address (x, v[0]). An rvalue is an unnamed temporary (5, a + b, a returned value): about to vanish, so its guts can be stolen.

Move semantics

Copying a million-element vector copies a million elements; if the source is a dying temporary that is waste. A move just steals the internal pointer.

  • std::move(x) moves nothing: it is a cast to an rvalue reference meaning "you may steal". The move constructor or assignment does the stealing.
  • A moved-from object is valid but unspecified: destroy or reassign it, do not read it.
  • Raw resource? Rule of Five, with noexcept moves: vector only moves on reallocation if the move cannot throw, else it copies.
The const trap std::move on a const object, or a type with no move operations, silently copies. So never return const values by value, and call std::move only on the last use.

Taking a parameter you will store

A constructor that stores its argument: take it by value and move (lvalue copied once, rvalue moved once). Not for setters: the extra construction can cost more than assignment.

No return std::move(local);Returning a local already allows elision (RVO/NRVO) or an automatic move. std::move blocks the elision.

Step through a shared object:

Reference cycles and weak_ptr

If A holds a shared_ptr<B> and B a shared_ptr<A>, neither is ever destroyed. Make one direction (the parent link) a weak_ptr.

One control block per object Never build a second shared_ptr from a raw pointer or from this. Copy an existing one, or inherit std::enable_shared_from_this and call shared_from_this().

Also: a stateful unique_ptr deleter makes it larger than a raw pointer; a shared_ptr's deleter is not part of its type; weak_ptr suits caches and observer lists too.

Ownership rules of thumb

Default to unique_ptr (or a plain value member); shared_ptr only for truly shared ownership. A raw pointer or reference means "I use it, I do not own it". Pass smart pointers by value only to transfer or share ownership.

Interview anglemake_unique/make_shared: no naked new (exception safe), less typing, and make_shared allocates once instead of twice.

auto x = {1,2,3}; is an initializer_list, not a vector. auto drops references and const: auto y = v[0]; copies; write const auto&. Same for for (auto [k, v] : map).

Lambdas

A lambda is an unnamed function object written in place.

PredictCapture by value vs by reference

byVal took a snapshot of x (1) when it was created. byRef sees the variable itself, so it reads the new value 2. A by-value capture is const inside the lambda unless you add mutable.

Dangling capturesA lambda that captures a local by reference and then outlives it (returned from the function, or run later on another thread) reads destroyed memory. When a lambda escapes its scope, capture by value.

std::function type-erases and may allocate. Prefer auto locally and a template parameter for functions taking a callable.

Exceptions and exception safety

  • Throw by value, catch by const& (by value slices).
  • Stack unwinding: leaving scopes runs destructors until a catch matches. This is why RAII is exception-safe.
  • A destructor must never throw: during unwinding that calls std::terminate. Destructors are implicitly noexcept.
  • noexcept promises no throw (enables optimisations such as vector moves); breaking it terminates.
  • Exceptions for exceptional failure, not control flow or real-time hot paths.
Exception safety levelPromise
No-thrownever throws (noexcept): swap, move, destructors
Strongif it throws, state is exactly as before (commit-or-rollback)
Basicif it throws, nothing leaks and invariants hold, but values may have changed

Interview cheat sheet

What does std::move actually do?

Nothing at runtime: it is an unconditional cast to an rvalue reference. It enables the move constructor or move assignment to be chosen. The moved-from object stays valid but unspecified. On a const object it silently copies, because a const rvalue cannot bind to a move constructor.

unique_ptr vs shared_ptr vs weak_ptr?

unique_ptr: sole owner, move-only, zero overhead. shared_ptr: reference-counted shared ownership with a control block and atomic count. weak_ptr: non-owning observer used to break cycles and to check whether a shared object is still alive (lock()).

Is shared_ptr thread-safe?

The reference count is atomic, so copying and destroying shared_ptrs from different threads is safe. The pointed-to object is not protected: concurrent access to it still needs synchronization. Concurrently modifying the same shared_ptr variable is also a race.

What is copy elision / RVO?

The compiler constructs a returned object directly in the caller's storage, skipping the copy or move. In C++17 it is guaranteed when returning a temporary (prvalue). Do not write return std::move(local): it prevents it.

What is stack unwinding?

When an exception propagates, the runtime exits scopes up the call stack, calling the destructors of all fully constructed locals until a handler is found. It is what makes RAII exception-safe.

Why should destructors not throw?

Destructors run during unwinding. If one throws while another exception is active, std::terminate is called. Destructors are noexcept by default; catch and handle errors inside them.

When would you use dynamic_cast?

For a checked downcast from a polymorphic base to a derived type when you cannot express the need through a virtual function. It returns null (pointers) or throws bad_cast (references) on failure. Frequent use suggests a design problem.

Difference between const and constexpr?

const means read-only after initialization (the value may be determined at runtime). constexpr means the value or function can be evaluated at compile time and usable in constant expressions.
