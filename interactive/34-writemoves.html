Writing Move Operations

How to write the move constructor and move assignment of a class that owns a resource, why they must be noexcept, and why the best answer is often to write nothing. Assumes Copy versus Move.

The move constructor, step by step

A class that owns a raw resource needs its own move constructor, because the compiler-generated one would copy the pointer and leave two owners. Steal the pointer and reset the source, so the source destructor frees nothing.

  • std::exchange(x, v) returns the old x and sets it to v: exactly "steal and reset".
  • After the move, o.data_ is nullptr, and delete[] nullptr is harmless, so the source can be destroyed safely.
  • A move constructor takes T&& (not const: it must change the source) and should be noexcept.

Move assignment and copy-and-swap

Move assignment must also release what the target already owns. The simplest correct version reuses the move constructor through copy-and-swap: take the parameter by value, then swap.

StyleGoodCost
copy-and-swap (by value)one function, handles self-assignment, strong guaranteean extra move or copy even when storage could be reused
operator=(const T&) plus operator=(T&&)can reuse existing storage, fastesttwo functions to write and keep correct
  • For a move assignment written by hand, check for self-assignment (if (this != &o)), free your own resource, then steal.
  • If you do not own a raw resource, write none of this (see below).

Why moves must be noexcept

std::vector promises that if growth throws, the vector is unchanged (the strong guarantee). Moving elements into the new buffer could throw halfway, so the vector uses std::move_if_noexcept: it moves only if the move is noexcept, and copies otherwise.

Element typeCopies during 8 push_backsMoves
move constructor not noexcept78
move constructor noexcept015
RuleMark move constructors and move assignments noexcept whenever they cannot throw. Moves that only swap or reset pointers never throw.

Rule of Zero first

The best move operations are the ones you do not write. If every member already knows how to copy and move itself, the compiler-generated operations are correct.

RuleYou writeWhen
Rule of Zeronothingmembers are vector, string, unique_ptr and so on
Rule of Fivedestructor, copy and move constructor, copy and move assignmentthe class owns a raw resource itself
  • Declare any of the five and the compiler stops generating some of the others: a user-declared destructor or copy operation suppresses the implicit moves, so a move silently becomes a copy.
  • To keep the defaults after declaring something, write = default explicitly.

Testing your move operations

You cannot see a move in the output, so test for it. A tiny counting type records every copy and move, and a test asserts the numbers you expect.

CheckWhat it proves
copies == 0 after building a vector of temporariesthe code moves instead of copying
std::is_nothrow_move_constructible_v<T> with static_assertthe move is really noexcept, so vector will use it
a moved-from object can be destroyed and assignedthe moved-from state keeps the class invariant
InvariantsA moved-from object must still be safe to destroy and to assign to. If your class promises "never empty", a move that empties it breaks the promise: reset to a valid state, or document that moved-from objects are special.

Cheat sheet

Answer aloud, then open.

Why mark a move constructor noexcept?

std::vector moves its elements on reallocation only if the move cannot throw; otherwise it copies them to keep the strong guarantee. Without noexcept every growth becomes a round of copies.

What does a move constructor do to the source object?

It steals the resources (pointers, handles) and resets the source to a safe empty state, for example with std::exchange(o.p, nullptr), so the source destructor frees nothing.

What is copy-and-swap assignment?

T& operator=(T o) { swap(*this, o); return *this; }: the parameter is copied or moved depending on the argument, then swapped in. The old contents are destroyed with o. It handles self-assignment and gives the strong guarantee.

What does the Rule of Zero say?

Do not write special member functions when members like vector, string and unique_ptr already manage themselves; the compiler's copy and move are then correct.

Why can declaring a destructor make moves slower?

A user-declared destructor stops the compiler generating move operations, so moves silently fall back to the copy operations.
