Returning Objects and Copy Elision

Why returning a big object by value is cheap: RVO, NRVO, guaranteed elision in C++17, and the few cases where std::move on a return helps. Assumes Writing Move Operations.

Returning a local: the compiler does the work

Returning an object by value sounds expensive. In practice the compiler removes the cost: it constructs the returned object directly in the storage of the caller, so no copy or move happens at all. This is copy elision, also called RVO (return value optimization) and, for a named local, NRVO.

So write it plainlyReturn locals and temporaries by value, with no std::move. The compiler either elides it or, if it cannot, moves it automatically.

Guaranteed elision in C++17

Since C++17 the elision of a temporary is mandatory, not an optimization. The object is never copied or moved, so the type does not need a copy or move constructor at all.

Kind of returnElisionIf the compiler does not elide
return Type(...); (a prvalue)guaranteed since C++17not possible: nothing to copy or move
return localName; (NRVO)allowed, done by all major compilers in simple casesthe local is moved automatically, never copied

When std::move on a return is right and wrong

Compiled with a counting type (copies and moves performed), these are all the common forms:

return std::move(c);01blocks NRVO: an extra move, so never write it

RuleReturn locals and temporaries plainly. Use std::move on a member, or on something that is not the local you are returning by name. -Wpessimizing-move (in -Wall) warns about the wrong one.

When elision does not happen

NRVO is allowed, not required, and it needs the compiler to know which object is the result. When it cannot decide, it falls back to a move: a returned local is treated as an rvalue first.

Return formResult
a single named local on every pathNRVO, no move
different locals on different pathsusually one move
a by-value parameterone move, never elided
a member or globalone copy, unless you std::move a member that you own
return cond ? a : b; with named objectsa copy: the conditional expression is an lvalue
Do not fight itWrite the natural code. If a profile shows a move you want to avoid, build the result in the caller (pass an output parameter) rather than adding std::move.

Cheat sheet

Answer aloud, then open.

What is copy elision / RVO?

The compiler constructs a returned object directly in the caller's storage, skipping the copy or move. In C++17 it is guaranteed when returning a temporary (prvalue). NRVO for a named local is allowed but not required. Do not write return std::move(local): it prevents it and costs a move.

Why is return std::move(local); a mistake?

It turns the returned expression into an xvalue, which blocks NRVO. The compiler then must move the object instead of building it in place: an extra move for nothing.

What changed about elision in C++17?

Returning a prvalue (a temporary such as return T();) is guaranteed to build the object directly in the caller's storage, so the type does not even need a copy or move constructor. Elision of a named local (NRVO) is still optional.

When is std::move on a return correct?

When you return a member of an object that outlives the call, or a by-value parameter's member: it is not the local being named, so no elision applies and moving avoids a copy.
