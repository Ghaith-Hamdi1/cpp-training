Initialization and brace traps

KindExampleNotes
aggregatePoint p{1, 2};no constructors: members set in order

Braces prefer initializer_list If a class has an initializer_list constructor, {...} picks it even when another constructor matches better (compiled: Widget w{1, 2} called the list constructor, Widget w(1, 2) the (int, int) one). Empty braces {} call the default constructor.
  • Initialize everything. An uninitialized local is indeterminate; reading it is undefined behaviour.
  • Braces catch accidental narrowing at compile time: a free safety check.
  • A static_cast in braces (int{x}) is a conversion that must not narrow.

auto, decltype and modern syntax

auto traps

auto y = v[0]; copies: write const auto& to avoid it. Same for for (auto [k, v] : map) (a copy of each pair). auto hides what a function returns: fine for iterators and lambdas, poor for public interfaces.

Implicit conversions and enum class

The compiler converts silently between arithmetic types. Compiled results of the classic surprises:

ExpressionResultWhy
-1 < 1ufalsethe signed value is converted to unsigned and becomes huge
uint8_t(200) + uint8_t(100)300, stored back as 44small types are promoted to int before arithmetic; storing back wraps
7 / 23integer division; 7 / 2.0 is 3.5
static_cast<int>(-3.9)-3conversion to an integer truncates toward zero
char 0xFF widened to int-1 (signed char)whether plain char is signed is implementation-defined
  • Usual arithmetic conversions: smaller than int becomes int; mixing signed and unsigned of the same rank converts to unsigned; int with double becomes double.
  • Never compare signed with unsigned (-Wsign-compare); use std::ssize or cast deliberately.
  • Single-argument constructors are implicit conversions: mark them explicit (OOP lesson).

Prefer enum class, with an explicit underlying type when the size matters: enum class Side : std::uint8_t { Buy, Sell };

Casts and type conversion

Four named casts replace the C cast (T)x: each states intent and is searchable.

CastUse forDanger
static_cast<T>(x)well-defined conversions: int to double, base to derived pointer when you are surelow
dynamic_cast<T>(x)checked downcast in a polymorphic hierarchy. Returns nullptr (pointer) or throws std::bad_cast (reference) on failureruntime cost; base needs a virtual function
const_cast<T>(x)add or remove const (legacy APIs)modifying a truly const object is UB
reinterpret_cast<T>(x)reinterpret raw bits (pointer to integer, unrelated pointer types)very high, rarely correct
RuleMany casts mean a design problem. Prefer virtual functions to dynamic_cast chains; no C casts.

const, constexpr and static

  • const: unchangeable after initialization. Use everywhere.
  • constexpr: computable at compile time (array sizes, template arguments), and still callable at runtime.

static means three things:

Local variable in a functionone instance that lives for the whole program and keeps its value between calls

Linkage and extern "C"

C++ mangles function names (it encodes the parameter types so that overloads get different symbols); C does not. To call C code, or to be called by it, tell the compiler to use C linkage:

  • An extern "C" function cannot be overloaded and cannot be a template or a member.
  • Pointers to extern "C" functions are technically a different type from C++ function pointers; compilers accept them for C callbacks in practice.
  • Linkage rules: a non-static, non-inline function defined in a header and included twice gives a "multiple definition" link error; mark it inline. extern on a variable declares it without defining it.

Interview cheat sheet

Answer aloud, then open.

When would you use dynamic_cast?

For a checked downcast from a polymorphic base to a derived type when you cannot express the need through a virtual function. It returns null (pointers) or throws bad_cast (references) on failure. Frequent use suggests a design problem.

The four named casts?

static_cast for well-defined conversions, dynamic_cast for checked downcasts, const_cast to add or remove const (modifying a truly const object is UB), reinterpret_cast to reinterpret bits (rarely correct). Never a C cast: it can silently pick any of them.

Difference between const and constexpr?

const means read-only after initialization (the value may be determined at runtime). constexpr means the value or function can be evaluated at compile time and used in constant expressions.

What does auto deduce, and what are its traps?

The type of the initializer with top-level const and references dropped. auto x = {1,2,3} is an initializer_list. auto y = v[0] copies; use const auto&. decltype(expr) keeps the exact type.

What is wrong with if (-1 < 1u)?

The signed operand is converted to unsigned, becoming a huge value, so the comparison is false. Avoid mixing signed and unsigned; compile with -Wsign-compare.

Why prefer enum class?

Its names are scoped (Level::Error) so they do not pollute the enclosing scope, and it does not convert implicitly to an integer. You can also fix its underlying type.

std::vector<int> v{3, 7} versus v(3, 7)?

Braces prefer the initializer_list constructor: two elements, 3 and 7. Parentheses call the (count, value) constructor: three elements, each 7.

What are the three meanings of static?

A local variable that lives for the whole program and keeps its value between calls; internal linkage for a global (visible only in this .cpp); a class member shared by all objects.

Which C++17 features do you use?

std::optional, std::variant, std::string_view, structured bindings, if constexpr, if with initializer, fold expressions and [[nodiscard]]: vocabulary types and clearer code.
