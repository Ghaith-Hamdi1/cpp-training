Iterators

An iterator acts like a pointer: *it, ++it, it == end. end() is one past the last; ranges are half-open [begin, end).

Inserters and iterator adaptors

An algorithm like std::copy assigns through its output iterator, so the destination must already be big enough. An inserter turns each assignment into an insertion instead:

AdaptorEach assignment does
std::back_inserter(c)c.push_back(x)
std::front_inserter(c)c.push_front(x) (so the order reverses; needs deque/list)
std::inserter(c, pos)c.insert(pos, x) (works for set and map)

std::reverse_iterator (what rbegin() returns) and std::move_iterator (moves instead of copying) are the other two adaptors worth knowing.

span and string_view: non-owning views

A view is a pointer plus a length: it looks at elements that someone else owns. std::span<T> (C++20) views any contiguous run of T; std::string_view (C++17) is the same idea for characters.

  • A span is two words (compiled: 16 bytes on a 64-bit machine). Pass it by value.
  • span<const int> is read-only; span<int> lets the function modify the elements in place. It still cannot grow or shrink the container.
  • It replaces the (T* data, size_t n) pair. Overflows are easier to spot, and a function written against span accepts a vector, an array, a std::array or a part of any of them.
  • Dangling. A view must not outlive what it looks at. A span of a vector that then reallocates (push_back), or a string_view of a temporary string, points at freed memory. Use views for parameters and short-lived local use, not for members that live longer than the data.
Rule of thumbTake a view to read or modify existing elements; take or return the owning type (vector, string) to keep them.

Cheat sheet

Answer aloud, then open.

What does std::back_inserter do and when do you need it?

It is an output iterator whose assignment calls push_back. Algorithms such as copy and transform write through iterators and do not grow the destination, so with an empty target you would write past the end; back_inserter makes them grow it instead.

Why can't I std::sort a std::list?

sort needs random-access iterators (it jumps around by index). A list only provides bidirectional iterators, so it has its own member function list::sort.

What does std::span replace, and what is its danger?

It replaces a (pointer, count) pair: a non-owning view of contiguous elements that remembers its size and accepts a vector, an array or a part of either, without copying. Like string_view it dangles if the data is destroyed or reallocated while the view is alive.

What is iterator invalidation, and when does push_back cause it?

A change to the container can leave existing iterators, pointers and references pointing at memory that no longer holds the element: using them is undefined behavior. vector::push_back invalidates all of them when it reallocates, otherwise only end(). Node-based containers (list, map, set) keep them valid except for an erased element.

Why is a range written [begin, end), and why compare with !=?

end() is one past the last element, so an empty range is simply begin == end and the length is end - begin. Only != works for every container; < exists only for random-access iterators.
