Pointers and References

Pointers, references and the memory they point at: where variables live, what an address is, arrays and decay, const, new and delete, and the bugs that follow. Assumes C++ Basics.

Memory is a row of numbered boxes

Your program's memory is a long row of numbered boxes, one per byte. The number of a box is its address. A variable is just a name for one or more boxes next to each other: an int takes 4 of them, and the address of the variable is the address of the first.

Made-up numbersThe addresses in this lesson are invented to keep the pictures readable. Real ones differ on every run.

Where variables live: stack, heap, static

Memory is split into regions with different lifetime rules. The rule decides where a variable should live.

RegionWhat goes thereLifetimeSpeed and size
Stacklocal variables, function parametersautomatic: freed when the scope { } endsvery fast, small (about 1 to 8 MB)
Heap (free store)objects created with new or mallocmanual: lives until you delete itslower, huge
Staticglobals, static variablesthe whole programfixed at startup
Mental modelStack: a pile of plates, popped automatically. Heap: a storage unit you rent until you hand the key back.

Pointers from scratch

A pointer is a variable whose value is an address. The type says what lives at that address, so a int* points to an int.

SyntaxMeaning
int* pdeclare p as "pointer to int"
&xaddress-of: the address of x
*pdereference: the thing p points to
p->mshorthand for (*p).m when p points to a struct
nullptrthe pointer that points to nothing

Step through it (addresses are made up):

CarefulDereferencing nullptr, an uninitialized pointer or a freed pointer is undefined behavior. C++ will not stop you.
What a pointer does not knowOnly an address and a type: not how many elements are there, nor who frees them. That is the root of most pointer bugs.
Key point"What is the difference between NULL and nullptr?" NULL is a macro for a null pointer constant, usually plain 0 (an integer), so f(NULL) can call f(int) instead of f(char*). nullptr has its own type and only converts to pointers.

Pointers and arrays

An array is a row of elements next to each other. Its name decays to a pointer to the first element, and p + 1 moves one element (not one byte).

The decay loses the size, which is the classic trap:

Instead ofUseWhy
int a[N]std::array<int, N>knows its size, no decay, same speed
new int[n]std::vector<int>grows, frees itself, .at(i) checks bounds
char* stringsstd::stringowns its memory, copies safely, has .size() and .find()
pointer plus a countstd::span<int> (C++20)a non-owning view that remembers its size

Dynamic memory: new and delete

new allocates on the heap and constructs the object; you must delete it, or it leaks. A heap object has three moments in its life, and the pointer outlives the last one.

BugWhat happened
Memory leakyou lost the pointer (or forgot delete) so the memory is never freed
Dangling pointeryou used a pointer after the memory was freed
Double deleteyou freed the same memory twice: undefined behavior, often a crash
Mismatchnew[] freed with delete, or the reverse
Modern C++Avoid raw new/delete: use std::vector and std::unique_ptr (Smart Pointers).
Key point"What does new do beyond malloc?" It calls the constructor, throws std::bad_alloc on failure (instead of returning null), and returns a correctly typed pointer. delete calls the destructor and then frees the memory.

Cheat sheet

Answer aloud, then open.

Pointer vs reference?

A pointer holds an address, can be null, can be re-pointed, and needs * to use. A reference is a permanent alias that must be initialized and cannot be null. Use references for parameters, pointers when "nothing" is a valid value or you need to re-point.

Stack vs heap?

The stack holds locals and is freed automatically when the scope ends; it is fast but small. The heap holds new-allocated objects that live until you free them; it is large but slower and you must manage the lifetime (or let a smart pointer do it).

What is a dangling pointer?

A pointer to memory that has been freed or has gone out of scope. Dereferencing it is undefined behavior. Setting a pointer to nullptr after delete helps, and smart pointers avoid the problem.

const int* vs int* const?

Read right to left. const int* is a pointer to a const int (data is read-only, pointer can move). int* const is a const pointer to an int (pointer is fixed, data can change).

delete vs delete[]?

Memory from new must be freed with delete; memory from new[] must be freed with delete[] so every element's destructor runs. Mixing them is undefined behavior. Deleting nullptr is safe and does nothing.
