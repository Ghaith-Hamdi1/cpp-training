Futures and async

To run a function in the background and get its result later, use a std::future<T>.

  • f.get() blocks until ready (once only); wait() and wait_for() do not take the value.
  • Exceptions travel: a throwing task rethrows from f.get().
  • Prefer tasks to raw threads: std::thread has no result channel and terminates on exceptions.
  • Pass std::launch::async; the default may defer the call to get().
  • An async future blocks in its destructor, so a discarded one makes the call effectively synchronous.

std::packaged_task routes a function's result into a future (how pools return results).

Thread pools and producer/consumer

A thread per task is expensive and thousands overload the scheduler. A thread pool starts N workers once; tasks go in a queue (producer/consumer).

It combines everything: mutex, condition variable, stop flag, RAII shutdown. The task runs outside the lock, or only one could run at a time.

Work stealing and sizing a pool

  • Work stealing is how production pools (TBB, Java's fork/join) balance load: each worker pops its own deque and an idle worker steals from another's back.
  • It suits recursive tasks that spawn subtasks: a spawned task goes on the spawner's own deque and stays hot in its cache.
  • A simple pool with one shared queue (the previous section) is fine until that queue's lock becomes the bottleneck. Know that stealing is the next step; do not claim to have written one.

Cooperative cancellation: jthread and stop_token

There is no safe way to kill a thread; you ask it to stop and it finishes its loop. std::stop_token is the standard channel for that request, and std::jthread joins in its destructor, which removes the "forgot to join" crash.

Parallel algorithms (C++17)

Most standard algorithms accept an execution policy as a first argument. The library decides how to split the work across threads.

PolicyMeaning
seqsequential, as without a policy
parmay run on several threads
par_unseqseveral threads and vectorised (SIMD): the function must not lock or allocate
  • Your function object must be thread-safe: no unsynchronised writes to shared data. A data race inside a parallel algorithm is still undefined behaviour.
  • std::reduce (not accumulate) is the parallel fold: it may reassociate the operation, so the operation must be associative (floating-point sums may differ slightly).
  • It only pays for big inputs and heavy work; for small ranges the thread overhead dominates.
  • With g++ you usually need Intel TBB installed and -ltbb for real parallelism; without a parallel backend the same code runs serially (as in the compiled example here).
  • Exceptions escaping the callback call std::terminate.
ChooseParallel algorithms for data parallelism over a container; a pool or std::async for independent tasks; a queue and a pinned thread for a latency-critical pipeline (Low-Latency C++).

Cheat sheet

Say each answer aloud, then open it.

std::async vs std::thread?

async returns a future carrying the result and any exception, and may use a pool or defer execution (use launch::async to force a thread). thread gives raw control with no result channel. A future from async blocks in its destructor.

What are promise, future and packaged_task?

A promise is the write end of a one-shot channel, a future the read end. A packaged_task wraps a callable and fulfils a future with its result or exception, which is how a pool returns results. A shared_future is a copyable read end for several waiters.

How would you signal several threads to start at the same moment?

A promise<void> whose shared_future every thread waits on, or a std::latch/barrier. The promise is one-shot; for repeated signals use a condition variable.

Why is the task run outside the lock in a thread-pool worker?

Otherwise only one task could run at a time, and the queue would stay locked while a task works. The worker takes the task under the lock, releases it, then runs the task.

How many threads should a pool have?

About hardware_concurrency() for CPU-bound work (more means oversubscription and context switches), more for I/O-bound or blocking work. Use separate pools for mixed workloads.

What is work stealing?

Each worker has its own deque of tasks and pops from it; an idle worker steals from the back of another's deque. Owners and thieves work at opposite ends, so contention is low and load balances automatically. It removes the single shared queue's lock as a bottleneck.

What is the difference between latch and barrier?

A latch is a one-shot countdown: threads count down and others wait until it reaches zero. A barrier is reusable: a fixed group of threads waits for each other at the end of each phase, then all continue together.

What does a semaphore do that a mutex does not?

A counting semaphore allows up to k threads in at once (a permit counter) and can be released by a different thread than the one that acquired it. A mutex is one owner at a time and must be unlocked by its owner.

How do you stop a thread cleanly?

Cooperatively: ask it to stop and let it return. C++20 std::jthread passes a std::stop_token that the loop checks, and its destructor requests the stop and joins. There is no safe forced kill.

When is a parallel algorithm worth using, and what must you watch?

For large inputs and non-trivial work per element. The callback must be thread-safe, reduce needs an associative operation, and small ranges are slower because of thread overhead. Without a parallel backend the call runs serially.
