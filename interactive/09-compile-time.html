Type Traits and Compile-time C++

Ask questions about types and compute values while compiling: <type_traits>, enable_if, if constexpr, constexpr and template metaprogramming.

Type traits

A type trait answers a question about a type at compile time (::value / _v) or transforms one (::type / _t).

Explore, especially the references and const rows, where people guess wrong:

Interview anglestatic_assert: compile-time, free. assert: run-time, gone when NDEBUG is defined.

enable_if and SFINAE

SFINAE: an invalid substitution drops that overload instead of erroring. std::enable_if uses it to switch overloads by a condition.

Noisy syntax, poor errors. Better tools:

constexpr, consteval, constinit

Write an ordinary function and ask for compile-time evaluation.

KeywordMeaning
constexpr variableMust be initialised with a constant expression; usable where constants are required (array sizes, template arguments).
constexpr functionCan run at compile time if its arguments are constants; can still be called at run time with ordinary values.
consteval (C++20)An "immediate" function: every call must be evaluated at compile time.
constinit (C++20)The variable is initialised at compile time (no static-initialisation-order problems), but remains mutable.

Template metaprogramming (TMP)

Before constexpr loops, compile-time computation was recursive template instantiation. You will meet it in old code and interviews.

Each Fact<N> is a separate class; the result is a baked-in constant.

  • Limits: recursion depth cap (a few hundred), slow builds, long errors.
  • Today: constexpr for values, traits + if constexpr/concepts for types; TMP only to compute types.

Interview cheat sheet

What does SFINAE stand for and why does it exist?Substitution Failure Is Not An Error: an invalid substitution while deducing a template removes that candidate from overload resolution instead of causing a hard error. It is what makes enable_if overload selection work.
std::is_same_v<int, const int>?False. They are different types. const and references are part of the type, which is why traits like std::decay_t and std::remove_cvref_t exist.
constexpr function versus consteval function?constexpr may run at compile time or run time. consteval must run at compile time and is a compile error otherwise.
Why is if constexpr better than if in a template?The discarded branch is not instantiated, so code that is invalid for some T does not break the build for that T.
How do you avoid writing the factorial struct by hand today?Write constexpr int factorial(int n) and use it in a constexpr context. It is shorter, readable and can also run at run time.
