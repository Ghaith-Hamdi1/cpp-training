Object-Oriented Programming in C++

Classes, object lifetime, copying, inheritance and polymorphism: what interviewers use to test whether you understand what a C++ object is. Assumes C++ Basics.

Classes and encapsulation

A class bundles data with the functions that use it. Encapsulation: keep data private, expose only operations that keep it valid.

SpecifierWho can access
publiceveryone
protectedthe class itself and classes derived from it
privateonly the class itself (and its friends)

"Valid" is the class invariant (here: balance never negative). Hide the representation, let constructors build only valid objects, keep the public interface small. No invariant to protect? Use a plain struct.

struct vs classOnly the default access differs: struct public, class private. Use struct for plain data.

Constructors and destructors

A constructor sets an object up; the destructor (~Name()) runs automatically when its lifetime ends. This is the basis of RAII.

  • Use the initializer list: it initializes members directly. const and reference members can only be set there.
  • Members initialize in declaration order, not list order (-Wreorder).
  • explicit on a one-argument constructor blocks silent conversions.

Order of construction and destruction

Construction: base, members, derived body. Destruction: the exact reverse.

Interview angleConstruct: base, members, derived body. Destruct: reverse.

Copying and the Rule of 3, 5 and 0

The compiler generates copy operations that copy every member. For a raw pointer that copies only the address: a shallow copy, and a bug:

Fix: a deep copy. Rule of Three: a custom destructor, copy constructor or copy assignment means you need all three.

RuleWhat you writeWhen
Rule of 0none of themThe goal. Hold resources in members that manage themselves: std::vector, std::string, std::unique_ptr.
Rule of 3destructor, copy ctor, copy assignThe class owns a raw resource and must define copying.
Rule of 5the 3 plus move ctor and move assignSame, and you also want cheap moves (see Core Language).

What the compiler still generates once you declare something

You declareCopyingMoving

a destructor, a copy constructor or a copy assignmentstill generated (but deprecated)not generated: an rvalue silently falls back to a copy
a move constructor or a move assignmentdisabledonly what you declared
  • A class can quietly lose its moves (a later logging destructor turns every move into a copy). Ask for defaults with = default; a polymorphic base needs them defaulted too.
  • Never = delete a move: it kills the copy fallback too. For a move-only type, delete the copy operations.
Best interview answer"Rule of Zero: vector and smart pointers make the generated members correct. Rule of Five only when wrapping a raw resource."

Member functions: this, const, static, friend

  • const member function: callable on const objects, cannot modify members (except mutable). Make getters const.
  • static member function: belongs to the class, no this.
  • friend: access to privates. Use sparingly.

Polymorphism and virtual functions

p->speak() through a base pointer reaches the derived behaviour only if speak is virtual. Without it the static type decides (compile time); with it the dynamic type (runtime). Try it:

How it works: vtable and vptr

Each class with virtuals has a vtable; each object has a hidden vptr to it. Cost: a pointer per object, an indirection per call, usually no inlining.

TermMeaning
Overloadingsame name, different parameters, resolved at compile time
Overridinga derived class replaces a virtual base function with the same signature, resolved at runtime
Hidinga derived function with the same name (but not virtual / different signature) hides the base one
Two famous traps

1. Always write override. If you mistype the signature (forget const), without it you silently create a new function instead of overriding.

2. Virtual calls inside a constructor or destructor do not reach the derived class. While Base's constructor runs, the object's dynamic type is Base, so Base::init() is called even if Derived overrides it.

Abstract classes and interfaces

= 0 makes a function pure virtual; a class with one is abstract (cannot be instantiated). Only pure virtuals and no data: an interface.

Operator overloading

Overload operators only when the meaning is obvious (+ on vectors, == on values, << to print).

  • Non-mutating binary operators (+, ==): non-member, so both sides convert. +=: member.
  • Keep usual semantics: == with !=, < a strict weak ordering. C++20 <=> generates all comparisons.
  • No new operators; :: . .* ?: cannot be overloaded.

Callable objects and conversions

operator() makes a class callable (the idea behind lambdas, std::function and comparators). Mark single-argument conversions explicit, as for constructors.

User-defined literals

A literal suffix is an operator you define: operator""_name. User suffixes must start with an underscore (the others are reserved for the standard library). Use them for units (ticks, basis points, bytes) so the meaning is in the code, not in a comment.

Interview cheat sheet

Why must a base class destructor be virtual?

If you delete a derived object through a base pointer and the destructor is not virtual, only the base destructor runs: undefined behavior, and the derived part's resources leak. A virtual destructor makes delete dispatch to the most derived destructor first. Any class meant to be a polymorphic base needs one.

What is the difference between overloading and overriding?

Overloading: several functions with the same name and different parameters in the same scope, chosen at compile time. Overriding: a derived class provides its own implementation of a base virtual function with the same signature, chosen at runtime.

What is a pure virtual function and an abstract class?

A pure virtual function is declared = 0 and has no required implementation. A class with at least one cannot be instantiated; it defines an interface that derived classes must implement.

What is the Rule of Three / Five / Zero?

Three: if you define a destructor, copy constructor or copy assignment, define all three. Five: add the move constructor and move assignment. Zero: design classes so none are needed by holding resources in self-managing members like vector and unique_ptr. Remember that declaring a destructor or a copy operation suppresses the move operations, so moves silently become copies.

What is object slicing?

Copying a derived object into a base-class value discards the derived members and virtual behaviour. Avoid it by passing polymorphic objects by reference or pointer.

What does explicit do?

It stops a constructor (or conversion operator) from being used for implicit conversions. Without it, void f(Account); f(5); could silently build an Account from 5.

Can a constructor be virtual? Can a destructor be pure virtual?

A constructor cannot be virtual: the vptr is set up by the constructor, so there is no dynamic type yet. A destructor can be pure virtual to make a class abstract, but it still needs a body because derived destructors call it.

Composition or inheritance?

Prefer composition. Use public inheritance only for a true is-a relationship where you need runtime polymorphism, and make sure it satisfies Liskov substitution.
