Object-Oriented Programming in C++

Classes, object lifetime, copying, inheritance and polymorphism. This is the lesson interviewers use to find out whether you understand what a C++ object really is. It assumes you know pointers and references from C++ Basics.

Classes and encapsulation

A class bundles data (members) with the functions that operate on it (member functions, or methods). The key idea is encapsulation: keep the data private and expose only operations that keep it valid.

SpecifierWho can access
publiceveryone
protectedthe class itself and classes derived from it
privateonly the class itself (and its friends)

The rule that decides what "valid" means is the class invariant, here "the balance never goes negative". Hide the representation, let constructors create only valid objects, and make every member function leave the object valid. If you cannot state an invariant, the type is probably plain data and should be a struct. Keep the public interface small, as small as possible but no smaller: put extras in non-member helper functions, which also leaves fewer places to look when something breaks.

struct vs classThey are the same thing except for defaults: struct members and inheritance are public by default, class ones are private. By convention, use struct for plain data and class when there are invariants to protect.

Constructors and destructors

A constructor runs when an object is created and sets it up. A destructor (~Name()) runs automatically when the object's lifetime ends: at the closing brace for locals, or on delete for heap objects. This automatic cleanup is the foundation of RAII (see Core Language).

  • Use the initializer list (after the colon). It initializes members directly. Assigning in the body means the member was default-constructed first and then overwritten. const and reference members can only be set in the list.
  • Members are initialized in declaration order, not in the order you write the list. Mismatched order is a classic warning (-Wreorder).
  • explicit on a one-argument constructor stops the compiler converting an int into your type behind your back.
  • Every object should start valid. Constructors guarantee it. A type with an obvious default gets a default constructor, which is why std::string s; is empty rather than garbage.

Order of construction and destruction

Base class first, then members (in declaration order), then the derived constructor body. Destruction is the exact reverse. Step through it:

Interview angle"In what order are constructors and destructors called with inheritance?" Construct: base, members, derived body. Destruct: derived body, members (reverse), base. This is also why a derived class can safely use its base while its own body runs.

Copying and the Rule of 3, 5 and 0

If you do not write them, the compiler generates a copy constructor and copy assignment operator that copy every member one by one. For an int that is perfect. For a raw pointer it copies only the address, which is called a shallow copy, and that is a bug waiting to happen:

The fix is a deep copy: give the class its own copy operations. This is the Rule of Three: if a class needs a custom destructor, copy constructor or copy assignment, it almost certainly needs all three.

RuleWhat you writeWhen
Rule of 0none of themThe goal. Hold resources in members that manage themselves: std::vector, std::string, std::unique_ptr.
Rule of 3destructor, copy ctor, copy assignThe class owns a raw resource and must define copying.
Rule of 5the 3 plus move ctor and move assignSame, and you also want cheap moves (see Core Language).

Member functions: this, const, static, friend

  • A const member function can be called on a const object, and the compiler stops it modifying members (except those marked mutable). Make every getter const.
  • A static member function belongs to the class, not an object, so it has no this.
  • friend grants a function or class access to private members. Use it sparingly: it weakens encapsulation.

Inheritance

Public inheritance models "is-a": a Dog is an Animal, so a Dog can be used anywhere an Animal is expected.

Object slicingCopying a derived object into a base value chops off the derived part: Animal a = Dog("Rex"); keeps only the Animal bits, and virtual behaviour is lost. Pass and store polymorphic objects by pointer or reference, never by value.

Mark a class final to forbid deriving from it. Prefer composition (see below) when the relationship is not truly is-a.

Polymorphism and virtual functions

Polymorphism lets you call p->speak() through a base pointer and get the derived class's behaviour. It only works if the base function is virtual. Without virtual the compiler picks the function from the pointer's static type at compile time. With virtual it picks from the object's real dynamic type at runtime. Try it, and watch what changes:

How it works: the vtable

A class with virtual functions gets a hidden table of function pointers (the vtable), one per class. Each object carries a hidden pointer to it (the vptr), set up by the constructor. A virtual call is: follow the vptr, index the table, jump. The cost is one extra pointer per object and one indirection per call, and the call usually cannot be inlined.

TermMeaning
Overloadingsame name, different parameters, resolved at compile time
Overridinga derived class replaces a virtual base function with the same signature, resolved at runtime
Hidinga derived function with the same name (but not virtual / different signature) hides the base one
Two famous traps

1. Always write override. If you mistype the signature (forget const), without it you silently create a new function instead of overriding.

2. Virtual calls inside a constructor or destructor do not reach the derived class. While Base's constructor runs, the object's dynamic type is Base, so Base::init() is called even if Derived overrides it.

Abstract classes and interfaces

A function declared = 0 is pure virtual. A class with at least one is abstract: you cannot create objects of it, only derive from it. A class with only pure virtual functions (and no data) is an interface.

Operator overloading

You can give operators meaning for your own types so they read naturally. Do it only when the meaning is obvious (+ on vectors, == on values, << for printing).

  • Binary operators that do not change their operands (+, ==) are best as non-member functions so both sides get implicit conversions; compound assignment (+=) is a member.
  • Keep the usual semantics: == and != together, < should be a strict weak ordering. C++20's operator<=> can generate all comparisons from one function.
  • You cannot invent new operators or change precedence, and ::, ., .*, ?: cannot be overloaded.

Composition, relationships and design

Ask "is it a, or does it have a?" Inheritance is the strongest coupling in C++; prefer composition unless you truly need polymorphism.

Interview cheat sheet

Why must a base class destructor be virtual?

If you delete a derived object through a base pointer and the destructor is not virtual, only the base destructor runs: undefined behavior, and the derived part's resources leak. A virtual destructor makes delete dispatch to the most derived destructor first. Any class meant to be a polymorphic base needs one.

What is the difference between overloading and overriding?

Overloading: several functions with the same name and different parameters in the same scope, chosen at compile time. Overriding: a derived class provides its own implementation of a base virtual function with the same signature, chosen at runtime.

What is a pure virtual function and an abstract class?

A pure virtual function is declared = 0 and has no required implementation. A class with at least one cannot be instantiated; it defines an interface that derived classes must implement.

What is the Rule of Three / Five / Zero?

Three: if you define a destructor, copy constructor or copy assignment, define all three. Five: add the move constructor and move assignment. Zero: design classes so none are needed by holding resources in self-managing members like vector and unique_ptr. Remember that declaring a destructor or a copy operation suppresses the move operations, so moves silently become copies.

What is object slicing?

Copying a derived object into a base-class value discards the derived members and virtual behaviour. Avoid it by passing polymorphic objects by reference or pointer.

What does explicit do?

It stops a constructor (or conversion operator) from being used for implicit conversions. Without it, void f(Account); f(5); could silently build an Account from 5.

Can a constructor be virtual? Can a destructor be pure virtual?

A constructor cannot be virtual: the vptr is set up by the constructor, so there is no dynamic type yet. A destructor can be pure virtual to make a class abstract, but it still needs a body because derived destructors call it.

Composition or inheritance?

Prefer composition. Use public inheritance only for a true is-a relationship where you need runtime polymorphism, and make sure it satisfies Liskov substitution.
