Vocabulary Types

The small standard types that make a function's contract visible in its signature: pair and tuple, optional, variant, expected and span. Builds on Types, Initialization & Casts.

Why vocabulary types

A signature like int find(const char* s) hides its contract: does -1 mean "not found"? Is s allowed to be null? Who owns the result? A vocabulary type puts the answer in the type, so every reader and the compiler see it.

All of them are ordinary value types: no heap allocation, no virtual functions, nothing to free.

pair, tuple and structured bindings

std::pair<A, B> holds two values, std::tuple<A, B, C...> any number. Structured bindings (C++17) unpack them into named variables.

  • A pair or tuple has no names: .first and std::get<2> say nothing about meaning. For a result that leaves a function and is used in more than one place, a small named struct reads better.
  • Comparison is built in and lexicographic: pairs and tuples compare element by element, so they work as map keys and in std::sort.
  • std::tie(a, b) = f(); assigns into existing variables; std::ignore skips one.
  • Structured bindings also unpack plain structs and arrays: auto [x, y] = point;. They are copies unless you write auto& or const auto&.

optional: a value or nothing

std::optional<T> holds either a T or nothing. The "nothing" is part of the type, so a caller cannot forget it exists.

  • The value lives inside the optional (compiled: sizeof(int) is 4, sizeof(optional<int>) is 8: the value plus a flag, padded). No heap allocation, unlike a pointer or unique_ptr.
  • Use it for a result that is legitimately absent: a lookup that may miss, a parse of untrusted input, an optional configuration value. It does not say why the value is missing; for that, use expected.
  • Not a replacement for a reference or pointer that means "refers to an object owned elsewhere": optional<T&> does not exist. Use a pointer there.
  • Marking a function [[nodiscard]] keeps callers from dropping the result.

variant and std::visit

std::variant<A, B, C> is a type-safe union: it holds exactly one of its alternatives and knows which.

Visiting every alternative

std::visit calls a function with whichever alternative is active. Give it a callable that handles every alternative, and a missing one is a compile error, not a silent bug.

  • Variant or virtual functions? A variant fits a closed set of types you control (messages, tokens, syntax-tree nodes), where you keep adding operations. Virtual functions fit an open set that others may extend. The trade-off is spelled out under Visitor in More Patterns.
  • If an alternative's constructor throws during assignment, the variant can end up valueless by exception (valueless_by_exception()). It is rare, and it is why you should keep alternatives cheap and non-throwing to move.
  • A reference alternative is ill-formed (use std::reference_wrapper). The same type twice is legal, but then you can only reach it by index, not by type.
  • std::monostate is an empty alternative: put it first to make a variant default-constructible when no alternative should be the default.

expected: a value or an error

std::expected<T, E> (C++23) holds either the result T or an error E. It is optional that explains why the value is missing, and an alternative to exceptions for failures that are normal.

It needs a C++23 standard library (GCC 12 or later, recent MSVC). With an older one, std::variant<T, E> or a small result struct does the same job, and the free tl::expected library has the same interface. Mark the function [[nodiscard]] so the result cannot be ignored.

span and string_view: non-owning views

A view is a pointer plus a length: it looks at elements that someone else owns. std::span<T> (C++20) views any contiguous run of T; std::string_view (C++17) is the same idea for characters.

  • A span is two words (compiled: 16 bytes on a 64-bit machine). Pass it by value.
  • span<const int> is read-only; span<int> lets the function modify the elements in place. It still cannot grow or shrink the container.
  • It replaces the (T* data, size_t n) pair. Overflows are easier to spot, and a function written against span accepts a vector, an array, a std::array or a part of any of them.
  • Dangling. A view must not outlive what it looks at. A span of a vector that then reallocates (push_back), or a string_view of a temporary string, points at freed memory. Use views for parameters and short-lived local use, not for members that live longer than the data.
Rule of thumbTake a view to read or modify existing elements; take or return the owning type (vector, string) to keep them.

Cheat sheet

Answer aloud, then open.

What is a vocabulary type?

A small standard type that expresses a common idea in a signature: optional (maybe a value), variant (one of several types), expected (a value or an error), span and string_view (a non-owning view). They replace magic values, tagged unions and pointer-plus-count pairs, so the contract is visible and checked.

optional versus a pointer for "may be absent"?

optional<T> holds the value itself (no heap allocation, no ownership question) and is empty when absent. A pointer means "refers to something owned elsewhere" and can be null. Use optional for a possibly missing value, a pointer for a possibly missing reference.

What happens on *opt, opt.value() and opt.value_or(x) when it is empty?

*opt is undefined behaviour, value() throws std::bad_optional_access, and value_or(x) returns x. Test with if (opt) first when you can.

How does std::variant differ from a union?

A variant remembers which alternative is active (index()), destroys the old one and constructs the new one on assignment, works with non-trivial types such as std::string, and throws bad_variant_access if you read the wrong one. A raw union does none of that, and reading the wrong member is undefined behaviour.

Why is std::visit safer than a chain of if / get_if?

The visitor must handle every alternative, so adding a type to the variant makes every incomplete visitor a compile error instead of a silent missing case. It also reads the active alternative without a manual check.

Variant or virtual functions for a set of message or shape types?

A variant when the set of types is closed and you keep adding operations: values are stored inline, there are no allocations or virtual calls, and the compiler checks completeness. Virtual functions when the set of types is open for others to extend and the operations are few.

optional, expected, exception or error code?

optional when "no value" needs no explanation. expected<T, E> (C++23) when the failure is normal and the reason matters. An exception for rare failures the local code cannot handle, and for constructors. An error code only at C boundaries.

What does std::span replace, and what is its danger?

It replaces a (pointer, count) pair: a non-owning view of contiguous elements that remembers its size and accepts a vector, an array or a part of either, without copying. Like string_view it dangles if the data is destroyed or reallocated while the view is alive.

How do you return several values from a function?

A std::pair or std::tuple, unpacked with structured bindings (auto [a, b] = f();), or a small named struct when the fields need names or the result travels. Not out-parameters, except where you want to reuse a buffer.
