Binary Data and Parsing

How a program turns bytes from the network into values: bit operations, struct layout, byte order, safe reads, zero-copy parsing, amounts and sequence numbers. Compiled examples are in examples/lessons/11-wire-formats.

From bytes to values

A network message arrives as bytes. The job: turn them into values quickly, correctly and without undefined behavior.

  • Never cast the buffer to a struct pointer. Copy fields out instead.
  • Check the length before every read. A truncated or corrupt packet must be rejected, not trusted.
  • Convert byte order explicitly. The network and your CPU may disagree.
The tempting wrong way That one line hides four problems: aliasing (undefined behavior), alignment (the buffer address may not suit a Sample), padding (the struct layout may not match the wire) and byte order. The next sections take them one by one.

Rules that bite

  • Use fixed-width types (std::uint8_t, std::uint32_t, std::int64_t) for anything on the wire; int and long change size between platforms (long is 32-bit on Windows).
  • Unsigned overflow wraps (well defined); signed overflow is undefined behavior.
  • Shifting by the type's width or more is undefined: write 1u << n with n < 32. Do bit work on unsigned types.
  • Small types are promoted to int in arithmetic. A plain char may be signed, so widening char(0xFF) to int gives -1: read bytes as unsigned char or std::uint8_t.

Struct layout, alignment and padding

Each type has an alignment (alignof): an int must start at a multiple of 4, a double or int64_t at a multiple of 8. The compiler pads between members to guarantee that, and pads the end so that arrays of the struct stay aligned. So sizeof is often bigger than the sum of the members.

Packing, and why not to rely on it

Packing is not freeA packed member may be unaligned: slower on some CPUs, a fault on others, and taking a reference or pointer to it is unsafe. Do not read the wire into a packed struct and use it directly. Read the bytes with memcpy (next sections) and keep ordinary structs inside your program. static_assert(sizeof(...)) is a cheap guard against accidental layout changes.

Endianness

  • Endianness is the order of a multi-byte value's bytes in memory. Network protocols traditionally use big-endian ("network byte order"); most desktop and server CPUs are little-endian. Protocols differ, so read each protocol's specification.
  • Convert at the boundary: when bytes enter the program, turn them into native values, and stay native inside.
  • Tools: ntohl/htonl (sockets), std::endian::native (C++20) to test the CPU, std::byteswap (C++23). The portable way that works everywhere is to assemble the value from bytes with shifts:

Widen each byte to uint32_t before shifting, otherwise it promotes to a signed int and shifting a large value into the top bit is a trap. The same code works on little- and big-endian machines, and compilers turn it into a single load plus a byte swap.

Reading bytes safely: aliasing and memcpy

Strict aliasing: you may access an object only through a pointer or reference of its own type (or a few related ones). Reading a uint32_t out of memory that holds something else is undefined behavior, and the optimizer is allowed to assume it never happens.

Zero-copy parsing

A zero-copy parser never copies the message: it keeps views (std::string_view, std::span) into the receive buffer and a cursor that advances. No allocation, no copying, no exceptions on the hot path.

  • std::from_chars (C++17) converts text to numbers with no allocation, no exceptions and no locale; it returns an error code and the pointer where it stopped. Compare with stoi (throws, needs a std::string) and stringstream (slow).
  • Validate everything before trusting it: length fields, tags, digits. Corrupt input is normal; return std::nullopt or an error code instead of throwing.
  • A view is valid only while the buffer is alive and unchanged. If the buffer is reused for the next packet, copy out what you need first.

Money amounts: fixed-point versus double

double cannot represent most decimal fractions exactly, so sums and comparisons drift. For money and amounts use an integer count of units: 101.2500 with a unit of 0.0001 is 1012500.

  • Exact and deterministic: the same inputs give the same bits on every machine, and equality needs no epsilon.
  • Parse from text directly into units; never go through double.
  • Watch overflow: int64_t holds about 9.2e18 units (9.2e14 amount units at 4 decimals). Multiplying amount by quantity can exceed that: check, or use a wider type (__int128 in GCC and Clang).
  • Decide the rounding rule (down, half-up, half-even) once, and apply it in one place.

Wrap-around: a 32-bit counter returns to 0 after 4294967295. Comparing with < breaks at that point; the unsigned subtraction followed by a signed reinterpretation keeps working as long as the two values are within 231 of each other. Expecting 4294967295 and receiving 0 is a gap of one, not a duplicate.

Cheat sheet

Answer aloud, then open.

Why not cast the receive buffer to a struct pointer?

Four problems at once: it violates strict aliasing (undefined behavior), the buffer address may not be aligned for the struct, struct padding may not match the wire layout, and the byte order may differ. Check the length, then copy each field out with memcpy or assemble it with shifts.

What is struct padding and how do you reduce it?

The compiler inserts unused bytes so each member sits at a multiple of its alignment, and pads the end so arrays stay aligned. sizeof can exceed the sum of the members. Order members from largest to smallest alignment; use static_assert(sizeof(...)) to guard the size.

What does #pragma pack(1) do, and what does it cost?

It removes padding so the struct matches a wire layout. The cost: members may be unaligned, which is slower or faults on some CPUs, and references or pointers to them are unsafe. Prefer reading fields with memcpy.

What is endianness? Which does the network use?

The order of a multi-byte value's bytes in memory. Little-endian stores the least significant byte first (x86, ARM), big-endian the most significant first. Network byte order is big-endian, though a given protocol may differ, so check the spec. Convert at the boundary.

How do you read a big-endian 32-bit value portably?

Assemble it from the bytes with shifts, widening each byte to uint32_t first: (uint32_t{p[0]} << 24) | (uint32_t{p[1]} << 16) | (uint32_t{p[2]} << 8) | uint32_t{p[3]}. It works on any CPU.

What is strict aliasing?

The rule that an object may only be accessed through an lvalue of its own type (or a few related types); the compiler assumes this when optimizing. Exceptions: char, unsigned char and std::byte may alias anything. Use memcpy or std::bit_cast to reinterpret bytes.

memcpy, bit_cast or a union for type punning?

memcpy and std::bit_cast (C++20) are well defined and compile to a plain load. Reading a different union member than was written is undefined behavior in C++, even though GCC allows it as an extension.

How do you set, clear and test a bit, and check for a power of two?

Set x | (1u << n); clear x & ~(1u << n); test (x >> n) & 1. Power of two: x != 0 && (x & (x - 1)) == 0. Use unsigned types and keep n below the width.

Why should amounts not be double?

Binary floating point cannot represent most decimals exactly (0.1 + 0.2 != 0.3), so sums and comparisons drift. Store an integer count of units (a scaled int64_t): exact, deterministic, and comparable with ==. Parse text straight into units and watch for overflow when multiplying by quantity.

Why std::from_chars in a parser?

It converts text to numbers without allocating, throwing or consulting the locale, and reports errors through a return value plus the position where it stopped. stoi throws and needs a std::string; stringstream is slow.

How do you detect a gap in sequence numbers, and handle wrap-around?

Compare the received number with the expected one: equal is in order, higher is a gap (lost messages: buffer and request a retransmission or snapshot), lower is a duplicate. For wrap-around compute static_cast<int32_t>(received - expected) and look at its sign.
