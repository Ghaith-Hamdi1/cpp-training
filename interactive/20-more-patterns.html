More Patterns and Feed-Handler Designs

Command with undo, Decorator, Adapter, Builder and Visitor with std::variant, with real code, plus the patterns that matter in a feed handler. Builds on Design Patterns.

Command (with undo)

Turn an action into an object. Because it is an object you can store it, queue it, log it, send it, replay it, and undo it.

Compiled: two appends gave "Hello, world", one undo gave "Hello".

  • Uses: undo/redo, task queues and thread pools (a task is a command), macro recording, transaction logs, and order messages that can be stored and replayed.
  • A lambda stored in a std::function is a lightweight command when you do not need undo.
  • Store enough state to reverse the action (the old value), not just the new one.

Decorator

Add behaviour to an object without changing its class by wrapping it in another object with the same interface. Wrappers stack.

  • vs inheritance: combinations multiply with subclasses (UpperBracketCompressed...), while decorators are chosen and stacked at run time.
  • Seen in: stream wrappers (buffered, compressed, encrypted), logging and metrics wrappers, retry and caching layers, middleware.
  • The cost is one virtual call and one allocation per layer: keep them out of hot paths.

Adapter

Make an interface you cannot change fit the one your code expects. The adapter implements the expected interface and translates each call.

  • Class or object adapter: the sample holds the adaptee as a member (object adapter, preferred). Private inheritance gives a class adapter.
  • A std::function or a lambda is often a quick adapter between two callable shapes. std::stack and std::queue are standard adapters over deque.
  • Adapter vs Decorator: an adapter changes the interface; a decorator keeps it and adds behaviour. Facade hides a subsystem behind a simpler interface.

Builder

Construct a complex object step by step with named steps, and validate at the end. Useful when a constructor would need many parameters.

  • Each setter returns *this so calls chain (a fluent interface). Validate in build(): an order without a symbol never gets out.
  • Alternatives in modern C++: an aggregate with designated initializers (Order{.sym = "ESZ5", .qty = 10}, C++20) is shorter when no validation is needed; named parameters via a small options struct.
  • The classic use is building trees or immutable objects; a builder avoids half-built objects.

Visitor and std::variant

Add a new operation over a closed set of types without editing them, by dispatching on the type. Classic C++ does it with double dispatch (accept(Visitor&) and one visit per type); modern C++ does it with std::variant and std::visit.

Virtual functionsvariant + visit
Add a new operationedit every classwrite one new visitor
Add a new typewrite one new classedit the variant and every visitor (the compiler reports the ones that do not handle it)
Storagepointers, heap, indirect callsvalues stored inline, no allocation, no virtual call
  • Use virtual functions when the set of types is open and operations are few; use variant + visit when the set of types is closed (message types, AST nodes, events) and you keep adding operations.
  • A forgotten alternative is a compile error, not a silent bug.
  • Variants are a natural fit for feed messages: std::variant<Add, Modify, Delete, Trade> and a visitor that updates the book.

Data such as the sequence number lives in the state that needs it, so it cannot be misused in another state. Interview cheat sheet

Say each answer aloud, then open it.

What is the Command pattern and how does it give you undo?

It turns a request into an object with execute (and undo). The invoker keeps executed commands on a stack; undo pops the last one and calls its undo. Because commands are objects they can also be queued, logged, sent and replayed (orders, thread-pool tasks, macros).

Decorator versus inheritance?

A decorator wraps an object with the same interface and adds behaviour, chosen and stacked at run time. Inheritance fixes the combination at compile time and multiplies classes for every combination. Streams with buffering or compression, and logging wrappers, are decorators.

Adapter versus Decorator versus Facade?

An adapter changes an interface to the one a client expects. A decorator keeps the interface and adds behaviour. A facade offers a simpler interface to a whole subsystem. std::stack and std::queue are adapters.

When would you use a Builder?

When an object has many optional or related parts, so a constructor would take a long argument list, or when it must be validated before use. Chain named setters and validate in build(). For simple aggregates, designated initializers (C++20) may be enough.

Visitor with virtual functions or with std::variant?

Virtual functions make adding a type easy and adding an operation hard. A variant with std::visit makes adding an operation easy (one new visitor), keeps values inline without allocation or virtual calls, and the compiler flags every visitor that misses a new alternative. Use it when the set of types is closed, such as message types.

How would you model a FIX or exchange session?

As a state machine: states such as Disconnected, LoggedOn and Stopped, each holding only its own data (for example the next expected sequence number), and an onEvent function that returns the next state. A variant of state structs with std::visit makes invalid combinations unrepresentable and avoids virtual calls.
