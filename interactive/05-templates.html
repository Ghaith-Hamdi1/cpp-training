C++ Templates

Templates let you write code once and have the compiler generate a version for every type you use. They power the whole standard library. This lesson goes from a first function template to forwarding references, variadic templates and type traits, the exact topics the job description lists.

Why templates, and function templates

Without templates you would write maxInt, maxDouble, maxString... identical except for the type. A template is a blueprint with the type as a parameter:

The compiler does not compile the template itself. Each time you use it with a new type it instantiates it: stamps out a real function with T replaced, then compiles that. This is compile-time polymorphism: no runtime overhead, but the code is generated per type (more binary size) and errors only appear when a bad type is used.

Interview angle"Templates vs virtual functions?" Templates resolve at compile time (static polymorphism): fastest, can be inlined, but every instantiation is separate code and types must be known at compile time. Virtual functions resolve at runtime: one piece of code, objects chosen dynamically, but a vtable indirection per call.

Class templates

The same idea for classes: std::vector<T>, std::map<K,V>, std::unique_ptr<T> are all class templates.

  • Non-type parameters (std::size_t Capacity) are compile-time constants, which is how std::array<int, 5> knows its size.
  • Each instantiation (Stack<int>, Stack<double>) is a completely separate class with no relationship to the others.
  • Member functions of a class template are only instantiated if you actually call them.
Why templates live in headersThe compiler needs the full definition at the point of instantiation. If you put a template's body in a .cpp file, other files see only the declaration and the linker reports undefined references. Put templates in headers (or use explicit instantiation template class Stack<int>; in the .cpp).

Specialization

Sometimes one type deserves a different implementation. A specialization overrides the generic template for specific arguments.

KindMeaningAllowed for
Full specializationall parameters fixed: template<> ... Printer<bool>class and function templates
Partial specializationa pattern: Printer<T*>class templates only
For functions, prefer overloadsYou cannot partially specialize a function template. Overload it instead (void f(int) next to template<class T> void f(T)): overload resolution prefers the non-template when it matches exactly. Function template specializations also do not take part in overload resolution, which surprises people.

Deduction and forwarding references

How T is deduced depends on how the parameter is written. The most important case is T&& in a function template: it is not an rvalue reference, it is a forwarding reference (also called a universal reference) that binds to anything and remembers whether it was an lvalue or rvalue. Explore the rules:

Is it really a forwarding reference?

Only when the type is deduced for that function and the form is exactly T&& (or auto&&). Everything else spelled && is an ordinary rvalue reference:

DeclarationForwarding reference?
template<class T> void f(T&& x)yes: T is deduced for f
auto&& x = expr;yes
template<class T> void f(std::vector<T>&& v)no: not exactly T&&, so it binds rvalues only
template<class T> void f(const T&& x)no: const disqualifies it
template<class T> struct S { void f(T&& x); };no: T is fixed by the class, so nothing is deduced for f
void f(Widget&& w)no: a plain rvalue reference

Reference collapsing

Deducing T = int& for T&& would mean a "reference to reference", which C++ resolves with a simple rule: if either is an lvalue reference, the result is an lvalue reference; only && + && stays an rvalue reference.

Perfect forwarding

Problem: a wrapper function takes arguments and passes them on to another function. Inside the wrapper the parameter has a name, so it is an lvalue, and the callee would always copy it. std::forward restores the original value category:

std::move vs std::forwardstd::move(x) always casts to an rvalue ("steal from this"). std::forward<T>(x) casts to an rvalue only if the original argument was an rvalue, and is used with forwarding references. Only use forward on a forwarding reference, and use it once.

Variadic templates and fold expressions

A parameter pack (typename... Args) lets a template take any number of arguments. You expand the pack with args.... Before C++17 you processed a pack by recursion: peel off the first element, recurse on the rest, and stop with a base case.

Type traits and if constexpr

<type_traits> lets code ask questions about types at compile time and even build new types from them.

if constexpr (C++17): compile-time branching

The condition is evaluated while compiling and the untaken branches are discarded, not even compiled, so each branch may use operations that are invalid for the other types. A normal if would fail to compile as soon as one branch did not make sense for T.

SFINAE and enable_if (the older way)

Substitution Failure Is Not An Error: if substituting a type into a template's signature produces invalid code, that overload is silently dropped from consideration instead of causing a compile error.

Interview cheat sheet

What happens when you use a function template?

The compiler deduces the template arguments from the call, then instantiates a concrete function for that combination of types (once per distinct combination across the program), and compiles it like normal code. The template itself generates no code.

What is a forwarding reference?

A T&& parameter where T is deduced for that very function template (or auto&&). It binds to lvalues and rvalues alike: for an lvalue T becomes X& and reference collapsing makes the parameter X&; for an rvalue T is X and the parameter is X&&. std::forward then preserves that category.

What is perfect forwarding, and why do we need it?

Passing arguments through a wrapper to another function without changing their value category or constness, so the callee can still choose copy vs move correctly. Without it you would need an overload per combination of lvalue/rvalue/const for every parameter.

Explain SFINAE.

If substituting deduced types into a function template's signature yields an invalid type or expression, that candidate is removed from the overload set rather than raising an error. std::enable_if exploits it to enable a function only for suitable types. C++17 if constexpr and C++20 concepts are the clearer modern tools.

Full vs partial specialization?

Full: all template arguments fixed. Partial: a pattern with some parameters still free (Foo<T*>), allowed for class templates and variable templates but not for function templates (use overloading).

Why must template definitions be in headers?

The compiler needs the body to instantiate it in each translation unit that uses a particular type. If only the declaration is visible, no instantiation happens and the linker cannot find the function. Alternative: explicit instantiation in one .cpp.

What is a variadic template and how do you process the pack?

A template taking zero or more arguments via a parameter pack (typename... Args). Expand with args.... Process by recursion with a base case, or in C++17 with a fold expression like (args + ...).

Templates vs inheritance for polymorphism?

Templates give static (compile-time) polymorphism: no runtime cost and inlinable, but the type must be known when compiling and each type duplicates code. Inheritance with virtual functions gives dynamic (runtime) polymorphism: one code path and heterogeneous collections, at the cost of an indirection and heap-allocated objects.
