Template argument deduction

When you call a function template, the compiler works out T from the arguments. The rule depends on the shape of the parameter, and it is the same rule auto uses.

ParameterCallDeduced TRule
T x (by value)f(ci) with const int ciinta copy: top-level const and references are dropped
T x (by value)f(arr) with int arr[3]int*arrays and functions decay to pointers
T& xf(ci)const intthe reference keeps the argument's const
T& xf(arr)int[3]an array keeps its size (usable to get its length)
const T& xf(5)intbinds temporaries; const is not part of T
T&& xf(i) / f(5)int& / intforwarding reference (see Forwarding references)

Compiled and checked with static_assert: by value, const int deduced int and the array deduced int*; by reference they deduced const int& and int(&)[3].

  • Deduction looks only at the arguments, never at the return type, and no conversions happen: maxOf(3, 2.5) fails because T would be both int and double.
  • Default arguments and braced lists do not take part in deduction: f({1, 2}) cannot deduce T. Name T explicitly: f<std::vector<int>>({1, 2}).
  • Name the type yourself when needed: maxOf<double>(3, 2.5).

Class template argument deduction (C++17)

The compiler deduces the class's arguments from the constructor call. A deduction guide tells it how when the constructors alone are not enough. All of the above was compiled and checked.

When deduction failsThe error says "couldn't deduce template parameter". Look for conflicting arguments, a braced list, or a parameter that does not mention T at all (e.g. only the return type does).

Class templates

Same idea for classes: vector<T>, map<K,V>, unique_ptr<T>.

  • Non-type parameters are compile-time constants (how std::array<int,5> knows its size).
  • Each instantiation is a separate, unrelated class. Members are instantiated only if called.
Why templates live in headersThe compiler needs the body at instantiation. In a .cpp, others see only a declaration: linker errors. Use headers, or explicit instantiation (template class Stack<int>;).

Forwarding references and perfect forwarding

T&& in a function template is a forwarding reference, not an rvalue reference: it binds to anything and remembers lvalue vs rvalue. Explore:

Is it really a forwarding reference?

Only when T is deduced for that function and the form is exactly T&& or auto&&:

DeclarationForwarding reference?
template<class T> void f(T&& x)yes: T is deduced for f
auto&& x = expr;yes
template<class T> void f(std::vector<T>&& v)no: not exactly T&&, so it binds rvalues only
template<class T> void f(const T&& x)no: const disqualifies it
template<class T> struct S { void f(T&& x); };no: T is fixed by the class, so nothing is deduced for f
void f(Widget&& w)no: a plain rvalue reference

Reference collapsing

Reference to reference collapses: any lvalue reference makes it an lvalue reference; only && + && stays rvalue.

Cheat sheet

How are template arguments deduced?

From the arguments of the call, by the shape of the parameter. By value (T x): const and references are dropped and arrays decay to pointers. By reference (T& x): const and the array size are kept. T&& is a forwarding reference. No conversions take part, so maxOf(3, 2.5) fails; name T explicitly.

What are alias templates and variable templates?

An alias template is a parameterised using (template<class T> using Vec = std::vector<T>;), which a typedef cannot be. A variable template is a constant or variable per type (template<class T> constexpr T zero = T{};); std::is_integral_v is one.

What happens when you use a function template?

The compiler deduces the template arguments from the call, then instantiates a concrete function for that combination of types (once per distinct combination across the program), and compiles it like normal code. The template itself generates no code.

What is a forwarding reference?

A T&& parameter where T is deduced for that very function template (or auto&&). It binds to lvalues and rvalues alike: for an lvalue T becomes X& and reference collapsing makes the parameter X&; for an rvalue T is X and the parameter is X&&. std::forward then preserves that category.

What is perfect forwarding, and why do we need it?

Passing arguments through a wrapper to another function without changing their value category or constness, so the callee can still choose copy vs move correctly. Without it you would need an overload per combination of lvalue/rvalue/const for every parameter.

Explain SFINAE.

If substituting deduced types into a function template's signature yields an invalid type or expression, that candidate is removed from the overload set rather than raising an error. std::enable_if exploits it to enable a function only for suitable types. C++17 if constexpr and C++20 concepts are the clearer modern tools.

Full vs partial specialization?

Full: all template arguments fixed. Partial: a pattern with some parameters still free (Foo<T*>), allowed for class templates and variable templates but not for function templates (use overloading).

Why must template definitions be in headers?

The compiler needs the body to instantiate it in each translation unit that uses a particular type. If only the declaration is visible, no instantiation happens and the linker cannot find the function. Alternative: explicit instantiation in one .cpp.

What is a variadic template and how do you process the pack?

A template taking zero or more arguments via a parameter pack (typename... Args). Expand with args.... Process by recursion with a base case, or in C++17 with a fold expression like (args + ...).

Templates vs inheritance for polymorphism?

Templates give static (compile-time) polymorphism: no runtime cost and inlinable, but the type must be known when compiling and each type duplicates code. Inheritance with virtual functions gives dynamic (runtime) polymorphism: one code path and heterogeneous collections, at the cost of an indirection and heap-allocated objects.
