Lvalues, rvalues and value categories

An lvalue has a name and an address (x, v[0]). An rvalue is an unnamed temporary (5, a + b, a returned value): about to vanish, so its contents can be stolen safely.

Copy versus move

Copying a million-element vector copies a million elements. If the source is a dying temporary, that is wasted work. A move just steals the internal pointer.

  • std::move(x) moves nothing: it is a cast to an rvalue reference meaning "you may steal". The move constructor or assignment does the stealing.
  • Overload resolution only looks at the kind of expression: an lvalue picks the copy, an rvalue picks the move.
  • A moved-from object is valid but unspecified: destroy it or assign a new value, do not read it. Compiled: a moved-from std::string had size 0, and assigning to it worked.

Writing move operations

A class that owns a raw resource needs the Rule of Five (OOP lesson). The move operations steal and leave the source safely empty:

  • std::exchange(x, v) returns the old x and sets it to v: the idiom for "steal and reset".
  • Mark moves noexcept. std::vector moves its elements on reallocation only if the move cannot throw; otherwise it copies them (exception safety).
  • The by-value operator= handles self-assignment and gives the strong guarantee. The classic pair operator=(const T&) and operator=(T&&) is faster when you can reuse the existing storage.
  • If you can avoid owning a raw resource, do (Rule of Zero): vector and unique_ptr members make the compiler-generated moves correct.

Sink parameters and move traps

Taking a parameter you will store

Compiled with a counting type: Holder(lvalue) and Holder(rvalue) together made 1 copy and 2 moves: the lvalue is copied once into the parameter, and each call moves once into the member. For a constructor that stores its argument, take it by value and move. Not for setters: the extra construction can cost more than assigning.

Cheat sheet

Answer aloud, then open.

What does std::move actually do?

Nothing at runtime: it is an unconditional cast to an rvalue reference. It enables the move constructor or move assignment to be chosen. The moved-from object stays valid but unspecified. On a const object it silently copies, because a const rvalue cannot bind to a move constructor.

What are lvalues, prvalues and xvalues?

An lvalue is a named object with an address. A prvalue is an unnamed temporary (a literal, a + b, a call returning by value). An xvalue is an object marked as movable, such as std::move(x). Rvalue means prvalue or xvalue. A named rvalue-reference parameter is still an lvalue inside the function.

What is copy elision / RVO?

The compiler constructs a returned object directly in the caller's storage, skipping the copy or move. In C++17 it is guaranteed when returning a temporary (prvalue). NRVO for a named local is allowed but not required. Do not write return std::move(local): it prevents it and costs a move.

Why mark a move constructor noexcept?

std::vector moves its elements on reallocation only if the move cannot throw; otherwise it copies them to keep the strong guarantee. Without noexcept every growth becomes a round of copies.

What state is a moved-from object in?

Valid but unspecified: you may destroy it or assign a new value to it, but not rely on its contents. For standard types it is usually empty.

How do you write a class that stores a string argument efficiently?

Take the parameter by value and std::move it into the member. An lvalue costs one copy plus one move, an rvalue costs one move, and there is a single function to write.

What is the difference between push_back and emplace_back?

push_back takes an existing object (copied or moved into the container). emplace_back forwards its arguments and constructs the element in place, saving a temporary. Both reallocate the same way.
