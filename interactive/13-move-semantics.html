Lvalues and Rvalues

The idea underneath move semantics: which expressions are named objects and which are temporaries, the three value categories, and which references bind to what. Assumes Copy Control and Operators.

Names and temporaries

Every expression in C++ is either something with a name and a place in memory that lives on after the statement, or a temporary that is about to vanish. This split is the whole foundation of move semantics: a temporary is safe to steal from, because nobody can look at it afterwards.

Quick testCan you take its address with &? Then it is an lvalue. If the compiler refuses, it is an rvalue.

Which reference binds to what

A reference type says which kinds of expression it accepts. That is how a function can tell whether it was given something it may steal from.

Overload resolution only looks at the kind of the argument: an rvalue prefers the && overload, everything else takes the const& one. A move constructor is simply the && overload of the copy constructor.

A name is always an lvalue

Inside a function that takes std::string&& s, the name s is an lvalue. The parameter can only bind to a temporary, but once it has a name you can use it twice, so it behaves like any named object.

Pass it on explicitlyTo hand a named rvalue reference to another function as an rvalue, write std::move(s) (or std::forward in a template, see Perfect Forwarding). Moving is always explicit in C++, so a name never gets stolen from by accident.

Cheat sheet

Answer aloud, then open.

What are lvalues, prvalues and xvalues?

An lvalue is a named object with an address. A prvalue is an unnamed temporary (a literal, a + b, a call returning by value). An xvalue is an object marked as movable, such as std::move(x). Rvalue means prvalue or xvalue. A named rvalue-reference parameter is still an lvalue inside the function.

What is the address test for lvalues and rvalues?

If you can take the address of an expression with &, it is an lvalue. A literal, a + b or the result of a call that returns by value is an rvalue and has no address.

Which reference types bind to an rvalue?

const T& and T&&. A plain T& binds only to lvalues. When both a const T& and a T&& overload exist, an rvalue chooses T&&.

Inside void g(std::string&& s), is s an lvalue or an rvalue?

An lvalue: it has a name and you can use it more than once. To pass it on as an rvalue you must write std::move(s).
