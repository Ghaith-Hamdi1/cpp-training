Lambdas

What a lambda is, how captures work and where they go wrong, init-capture, generic lambdas, and where lambdas are used. Assumes Function Pointers and Functors.

What a lambda is

A lambda is a function you write right where you need it, with no name. It has three parts: what it can see from outside (the captures), what it receives (the parameters), and what it does (the body).

  • Every lambda has its own unique type, so store it with auto (or a template parameter).
  • A lambda with no captures converts to a plain function pointer. Compiled: sizeof of a lambda with no captures is 1, of one capturing an int is 4, of a function pointer 8.
  • operator() is const by default; mutable lifts that (see below).
Where it comes fromA lambda is a functor that the compiler writes for you. If functors are new, read Function Pointers and Functors first.

Captures: by value and by reference

The square brackets say which outside variables the lambda may use, and how it holds them. By value copies the variable into the lambda when it is created. By reference keeps an alias to the live variable.

PredictCapture by value vs by reference

byVal took a snapshot of x (1) when it was created. byRef sees the variable itself, so it reads the new value 2. A by-value capture is const inside the lambda unless you add mutable.

Step through the two capture modes:

CaptureMeaning
[]nothing from outside
[x]a copy of x
[&x]a reference to x
[=]copy everything the lambda uses
[&]reference everything the lambda uses
[x = expr]a new member initialized from expr (see below)
Prefer naming themA list such as [limit, &total] shows at a glance what the lambda depends on. [=] and [&] hide it.

Capture lifetime: dangling references

A by-reference capture is only valid while the variable lives. If the lambda outlives it, because it is returned, stored, or run later on another thread, the reference points at a destroyed variable.

The lambda is...Capture by reference is...
used and finished inside the same scope (std::sort, count_if)safe
returned or stored for laterdangling: capture by value
run on another thread that may outlive the variabledangling: capture by value
[=] and thisInside a member function [=] also captures this (the pointer), so the lambda uses the object through that pointer and dangles if the object dies. This implicit capture is deprecated in C++20: write [=, this] to say so, or [*this] to copy the object.

mutable, init-capture, generic and recursive lambdas

mutable: the lambda's own state

A by-value capture is const inside the lambda; mutable lets it change. The change lives in the lambda's own copy, never in the original variable, and each copy of the lambda has its own state.

Init-capture: move something in

[name = expr] creates a new member initialized from expr. It is the way to move a unique_ptr in, or to precompute a value once.

Generic lambdas

With auto parameters (C++14) the lambda's operator() is a template, so one lambda works for any types that support <.

Where lambdas are used

Almost everywhere something takes a small piece of behavior.

SituationExample
sort with your own orderstd::sort(w.begin(), w.end(), [](const std::string& a, const std::string& b) { return a.size() < b.size(); });
find or count by a rulestd::find_if(v.begin(), v.end(), [](int x) { return x % 2 == 0; });
a task for a threadstd::thread t([&] { work(); }); (capture carefully, see lifetime)
a callback you keep for laterstd::function<void()> onDone = [id] { notify(id); };
initialize a const with logicconst auto v = [&] { ... }();

Compiled: sorting {"pear", "fig", "banana"} with the length comparison above put fig first and banana last.

Rule of thumbIf the logic is more than a few lines, or you use it in several places, give it a name (a function) instead of a long lambda.

Cheat sheet

Answer aloud, then open.

What is a lambda and what does the compiler generate?

An unnamed function object: the compiler creates a unique class with the captured variables as members and the body as operator(). Because it has its own type, calls can be inlined.

Capture by value vs by reference?

By value copies the variable when the lambda is created (const inside unless mutable). By reference stores a reference to the live variable and dangles if the lambda outlives it. Capture by value for lambdas that escape the scope or run on another thread.

How do you move a unique_ptr into a lambda?

With a C++14 init-capture: [p = std::move(ptr)] { ... }. A plain capture would need a copy, which unique_ptr forbids.

What does mutable do on a lambda?

It makes operator() non-const so the lambda can modify its by-value captures. The changes live in the lambda's own copy, not in the original variable.

What is a generic lambda?

A lambda with auto parameters (C++14): its operator() is a template, so one lambda works for any argument type.

What is wrong with capturing this by [=]?

[=] inside a member function captures the this pointer, not a copy of the object, so the lambda dangles if the object is destroyed first. It is deprecated in C++20: write [=, this] or [*this] to copy.
