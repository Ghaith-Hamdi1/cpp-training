Lambdas and Callables

How a lambda works, captures and their lifetime traps, init-capture, generic lambdas, and when to use a function pointer, functor, lambda or std::function.

What a lambda is

A lambda is an unnamed function object written in place: the compiler generates a small class whose constructor stores the captures and whose operator() holds the body.

  • Every lambda has its own unique type, so store it with auto (or a template parameter).
  • A lambda with no captures converts to a plain function pointer. Compiled: sizeof of such a lambda is 1, of one capturing an int is 4, of a function pointer 8.
  • operator() is const by default; mutable lifts that (next sections).

Captures: by value and by reference

PredictCapture by value vs by reference

byVal took a snapshot of x (1) when it was created. byRef sees the variable itself, so it reads the new value 2. A by-value capture is const inside the lambda unless you add mutable.

Step through the two capture modes:

Dangling capturesA lambda that captures a local by reference and then outlives it (returned from the function, or run later on another thread) reads destroyed memory. When a lambda escapes its scope, capture by value.
[=] and thisInside a member function [=] also captures this (the pointer), so the lambda uses the object through that pointer and dangles if the object dies. This implicit capture is deprecated in C++20: write [=, this] to say so, or [*this] to copy the object.

mutable, init-capture, generic and recursive lambdas

  • Init-capture [name = expr] creates a new member: the way to move a unique_ptr in, or to precompute something.
  • mutable changes the lambda's own copy; each copy of the lambda has its own state.
  • A generic lambda has a templated operator(): auto parameters are template parameters.
  • A lambda cannot name itself. For recursion, pass it to itself: auto fact = [](auto self, int n) -> int { return n <= 1 ? 1 : n * self(self, n - 1); }; (compiled: 5! = 120), or use std::function.
  • [this] in a member function captures the pointer; [*this] copies the object.

  • Templates for hot paths and algorithms (std::sort takes its comparator as a template parameter and inlines it). std::function when you must store callables of different types or keep them behind an interface.
  • std::function may allocate when the callable does not fit its small buffer. Compiled with libstdc++: a small capture did not allocate, a 64-byte capture did.
  • std::invoke(f, args...) calls anything callable, including a member function pointer: std::invoke(&Account::balance, acct).
  • A stateless lambda converts to a function pointer, handy for C APIs and callbacks.

std::bind: know it, prefer a lambda

Compiled: f(2, 3) gave 123, g(4, 5) gave 549 and the lambda gave 123. std::bind predates lambdas (C++11); it copies its arguments, hides overloads and produces unreadable errors. You will see it in older code, so be able to read it; in new code write a lambda, which also inlines better.

Interview angle"Lambda vs std::function?" A lambda has its own type and is inlined; std::function erases the type, costs an indirect call and maybe an allocation. Use it only when you must store different callables in one place.

Interview cheat sheet

Answer aloud, then open.

What is a lambda and what does the compiler generate?

An unnamed function object: the compiler creates a unique class with the captured variables as members and the body as operator(). Because it has its own type, calls can be inlined.

Capture by value vs by reference?

By value copies the variable when the lambda is created (const inside unless mutable). By reference stores a reference to the live variable and dangles if the lambda outlives it. Capture by value for lambdas that escape the scope or run on another thread.

How do you move a unique_ptr into a lambda?

With a C++14 init-capture: [p = std::move(ptr)] { ... }. A plain capture would need a copy, which unique_ptr forbids.

What does mutable do on a lambda?

It makes operator() non-const so the lambda can modify its by-value captures. The changes live in the lambda's own copy, not in the original variable.

std::function vs a template parameter?

A template parameter keeps the exact callable type, so the call is inlined and nothing allocates. std::function erases the type: one indirect call, possible allocation, but it can store different callables behind one type.

What is a generic lambda?

A lambda with auto parameters (C++14): its operator() is a template, so one lambda works for any argument type.

What is wrong with capturing this by [=]?

[=] inside a member function captures the this pointer, not a copy of the object, so the lambda dangles if the object is destroyed first. It is deprecated in C++20: write [=, this] or [*this] to copy.
