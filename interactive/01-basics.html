C++ Basics and Pointers

Start here if C++ is new or rusty. By the end you will understand types, functions, where variables live in memory, and how pointers and references really work. Every other lesson builds on this one.

How a C++ program is built

C++ is a compiled language: your source code is translated into machine code before it runs. There is no interpreter watching over it, which makes C++ fast but also means the language trusts you not to make memory mistakes.

  1. Preprocess: #include literally pastes header files in; #define does text substitution.
  2. Compile: each .cpp file becomes an object file on its own.
  3. Link: the linker joins object files and libraries into one executable and resolves calls between files.
Habit to build nowAlways compile with -Wall -Wextra. The compiler warns about many of the bugs this lesson describes (uninitialized variables, unused values, signed/unsigned comparisons).
Interview angle"Compile error vs linker error?" A compile error is a syntax or type problem inside one file. A linker error ("undefined reference") means a function was declared and called but never defined anywhere you linked.

Variables and types

Every variable has a type that fixes how much memory it uses and what you may do with it.

TypeHoldsTypical size
booltrue / false1 byte
chara character / small integer1 byte (always, by definition)
intwhole number4 bytes

float / doubledecimal number4 / 8 bytes

Sizes other than char are only guaranteed as minimums, so when size matters use the fixed-width types from <cstdint>: std::int32_t, std::uint64_t and so on.

Initialization: always give a variable a value

Undefined behaviorA local variable you never initialize contains garbage left over in memory. Reading it is undefined behavior (UB): the program may print junk, crash, or appear to work until the day it does not.

The signed/unsigned trap

unsigned types never go negative; they wrap around instead. Mixing signed and unsigned in a comparison converts the signed value to unsigned first.

PredictWhat does this print?

It prints 0 (false). -1 is converted to unsigned and becomes 4294967295, which is not less than 1. This is why -Wall -Wextra warns about sign comparisons, and why you should be careful comparing an int index with vector::size() (an unsigned type).

Operators and control flow

PredictPrefix vs postfix

x++ yields the old value and then increments, so a is 5 and x becomes 6. ++x increments first (x becomes 7) and yields the new value, so b is 7.

Classic bugif (x = 5) assigns 5 to x and is always true. You meant ==. The compiler warns with -Wall.

Functions and passing arguments

A function must be declared before it is called. A declaration (prototype) says the name and types; the definition supplies the body. Headers hold declarations so many files can share them.

Where variables live: stack, heap, static

Pointers only make sense once you know there are different regions of memory.

RegionWhat goes thereLifetimeSpeed / size
Stacklocal variables, function parametersautomatic: freed when the scope { } endsvery fast, small (about 1 to 8 MB)
Heap (free store)objects created with new / mallocmanual: lives until you delete itslower, huge
Static / globalglobals, static variableswhole programfixed at startup
Mental modelThe stack is a pile of plates: push one per function call, pop it when the call returns, everything on it vanishes automatically. The heap is a storage unit you rent: it stays yours until you hand the key back.

Pointers and arrays

An array name decays to a pointer to its first element, and adding 1 to a pointer moves it by one element (not one byte).

CarefulNever dereference nullptr and never read past the end of an array. Both are undefined behavior. C++ will not stop you.
What a pointer does not knowA pointer holds an address and a type, and nothing else. It does not know how many elements it points to, or who must free them, which is the root of most pointer bugs. It is also not an integer: int* and char* are different types and the compiler refuses to mix them, because writing an int through a char* would trample the neighbouring memory.
Interview angle"What is the difference between NULL and nullptr?" NULL is the integer 0 in disguise, so f(NULL) can call f(int) instead of f(char*). nullptr has its own type and only converts to pointers.

References

A reference is an alias: another name for an existing variable. It is not a copy and it adds no new variable.

Pointer int*Reference int&
Can be nullyesno (must refer to something real)
Must be initializedno (but should be)yes, at declaration
Can be re-pointedyesno, bound for life
Syntax to use*p, p->memberjust use the name
Use foroptional things, arrays, ownership, C APIsfunction parameters, aliases
PredictThe reference trap

r = b does not make r refer to b. References cannot be re-bound. It assigns the value of b into the variable r aliases, so a becomes 2.

const and pointers

const means "I promise not to modify this". With pointers there are two things that can be const: the pointed-to value and the pointer itself. Read the declaration right to left.

Rule of thumbWhatever is to the left of the * is the pointed-to data; whatever is to the right is the pointer. const before the star protects the data.

Make everything const that can be. It documents intent and lets the compiler catch mistakes. Prefer const T& parameters for big read-only objects.

Dynamic memory: new and delete

new allocates on the heap and constructs the object, then returns a pointer. You must give the memory back with delete or it leaks.

BugWhat happened
Memory leakyou lost the pointer (or forgot delete) so the memory is never freed
Dangling pointeryou used a pointer after the memory was freed (see the step-through above)
Double deleteyou freed the same memory twice: undefined behavior, often a crash
Mismatchnew[] freed with delete, or the reverse
Modern C++ ruleAvoid raw new and delete in new code. Use std::vector for arrays, and std::unique_ptr / std::make_unique for single objects: they free memory automatically. You will meet them in the Core Language lesson.
Interview angle"What does new do beyond malloc?" It calls the constructor, throws std::bad_alloc on failure (instead of returning null), and returns a correctly typed pointer. delete calls the destructor and then frees the memory.

Arrays, C-strings and std::string

C-style arrays and strings are error-prone. In C++ you should almost always use:

Instead ofUseWhy

Interview cheat sheet

Try answering each one out loud before opening it.

Pointer vs reference?

A pointer holds an address, can be null, can be re-pointed, and needs * to use. A reference is a permanent alias that must be initialized and cannot be null. Use references for parameters, pointers when "nothing" is a valid value or you need to re-point.

Stack vs heap?

The stack holds locals and is freed automatically when the scope ends; it is fast but small. The heap holds new-allocated objects that live until you free them; it is large but slower and you must manage the lifetime (or let a smart pointer do it).

What is a dangling pointer?

A pointer to memory that has been freed or has gone out of scope. Dereferencing it is undefined behavior. Setting a pointer to nullptr after delete helps, and smart pointers avoid the problem.

const int* vs int* const?

Read right to left. const int* is a pointer to a const int (data is read-only, pointer can move). int* const is a const pointer to an int (pointer is fixed, data can change).

delete vs delete[]?

Memory from new must be freed with delete; memory from new[] must be freed with delete[] so every element's destructor runs. Mixing them is undefined behavior. Deleting nullptr is safe and does nothing.

What is undefined behavior?

Code the standard places no requirements on: the compiler may assume it never happens, so anything can occur (crash, wrong output, or apparently fine). Examples: out-of-bounds access, null dereference, signed overflow, reading uninitialized memory, data races.

How do you pass a large object to a function efficiently?

By const reference if the function only reads it, to avoid a copy. By non-const reference if it must modify the caller's object.
