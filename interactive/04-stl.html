vector: the workhorse

A vector is one contiguous heap array with a size and a capacity. When full, push_back allocates a bigger buffer, moves everything and frees the old one: occasional O(n), amortised O(1).

reserve vs resizereserve(n) only allocates; resize(n) creates elements. v[5] = x after only reserve(10) is UB.

Container adaptors

They wrap another container and restrict the interface: std::stack (LIFO: push/pop/top), std::queue (FIFO: push/pop/front) and std::priority_queue (a heap: top() is the largest element by default).

Cheat sheet

Answer aloud, then open.

How does std::vector grow?

When size == capacity it allocates a larger buffer (geometric growth, typically 1.5x to 2x, implementation-defined), moves or copies the elements, and frees the old buffer. This makes push_back amortised O(1), but it invalidates all iterators, pointers and references. reserve avoids the reallocations.

push_back vs emplace_back?

push_back takes an existing object (a copy or move). emplace_back forwards its arguments to the element's constructor and builds it in place, avoiding a temporary. For simple types there is no difference; for objects with expensive construction emplace_back can save a move.

Which container for a task queue? For "top K" elements?

A queue (std::queue, backed by deque) for FIFO tasks. A priority_queue (heap) for top K: keep a heap of size K and compare against its root: O(n log K).

How do you return several values from a function?

A std::pair or std::tuple, unpacked with structured bindings (auto [a, b] = f();), or a small named struct when the fields need names or the result travels. Not out-parameters, except where you want to reuse a buffer.
