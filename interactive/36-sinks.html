Sink Parameters and Move Traps

Taking a parameter that you will store: by value and move versus overloads, the traps that turn a move into a copy, and push_back versus emplace_back. Assumes Returning Objects and Copy Elision.

Taking a parameter you will store

A function that stores its argument (usually a constructor) wants to copy an lvalue and move an rvalue. The simplest way to get both: take the parameter by value, then move it into place.

Compiled with a counting type: one lvalue call and one rvalue call together made 1 copy and 2 moves.

By value, overloads or const reference?

Three ways to write a constructor that stores its argument:

Stylelvalue argumentrvalue argumentFunctions to write
by value, then std::move1 copy + 1 move2 movesone
overloads const T& and T&&1 copy1 movetwo
only const T&1 copy1 copyone (slower for temporaries)
  • By value costs one extra move compared with two overloads. For cheap-to-move types that is the best trade for the saving in code.
  • Two overloads are fastest, and worth it when a move is expensive or the function is on a hot path (compiled: 1 copy, 1 move).
  • Do not use by-value sinks for setters: assigning into an existing member can reuse its storage, while a by-value parameter always allocates first.
  • For types that are cheap to copy (int, a pointer), just take them by value and do not move.

Move traps

The move operations are only used when everything lines up. These are the usual ways they are not:

TrapWhat happens
std::move on a const objectcopies: a const T&& cannot bind to T&& (compiled: 1 copy, 0 moves)
a type with no move operationssilently copies
using an object after std::movevalid but unspecified; only destroy or assign to it
std::move on a forwarding reference parametermoves an lvalue the caller still wanted: use std::forward
moving inside a loopthe second iteration sees a moved-from object
return std::move(local);blocks elision: an extra move
Move only the last useAfter auto b = std::move(a); treat a as empty. Do not assume a move happened: Effective Modern C++ Item 29 says to assume moves may be absent, not cheap and not used.

push_back, emplace_back and moving into containers

Adding to a container is the most common place to move or copy.

CallWhat it does
v.push_back(lvalue)copies the object into the container
v.push_back(std::move(x)) or push_back(temp)moves it in
v.emplace_back(args...)builds the element in place from the arguments, with no temporary
  • For a type that is cheap to build from its arguments, emplace_back saves the temporary and the move.
  • If you already have an object, push_back(std::move(obj)) is just as good.
  • Both can reallocate, and reallocation moves or copies the existing elements (see Writing Move Operations).

Move-only sinks

For types that cannot be copied (unique_ptr, std::thread, a file handle) a by-value parameter is the natural sink: the caller must write std::move, so the transfer of ownership is visible.

ParameterMeaning for a move-only type
std::unique_ptr<T>sink: the function owns it
std::unique_ptr<T>&the function may reseat the caller's pointer
const std::unique_ptr<T>&pointless: pass T& or T* to just use the object
std::unique_ptr<T>&&possible, but the by-value form is clearer

The same pattern is used by std::thread's constructor and by containers of unique_ptr: v.push_back(std::move(p)).

Cheat sheet

Answer aloud, then open.

How do you write a class that stores a string argument efficiently?

Take the parameter by value and std::move it into the member. An lvalue costs one copy plus one move, an rvalue costs one move, and there is a single function to write.

What is the difference between push_back and emplace_back?

push_back takes an existing object (copied or moved into the container). emplace_back forwards its arguments and constructs the element in place, saving a temporary. Both reallocate the same way.

When should a sink parameter not be taken by value?

For setters and other functions that assign into an existing object: assignment can reuse existing storage, while a by-value parameter always constructs a new object first. Also when the type is expensive to move, where two overloads are better.

List three traps that make a move silently a copy.

std::move on a const object, a type without move operations (or whose moves were suppressed by a user-declared destructor), and a forwarding reference passed on with std::move or without std::forward.
