Strings, Regex and Time

Text in C++: ownership with string and string_view, how a string stores its characters, converting numbers, formatting and streams, then <regex> and <chrono>.

std::string and std::string_view

std::string owns its characters. std::string_view (C++17) is a non-owning pointer plus length: two words, no allocation, valid only while the text lives.

Classic bug: dangling view A view must not outlive its string and is not null-terminated: do not pass sv.data() to a C API.
  • SSO: short strings (about 15 chars) live inside the object, no heap allocation.
  • string_view for read-only parameters; std::string for what you store.
  • Building big strings in a loop: append or reserve, not chained + temporaries.
Interview angleView when you only read (accepts literals without a temporary); const string& when you need null termination.

Inside std::string: SSO and capacity

A std::string is a small object (compiled: 32 bytes, libstdc++) that holds a pointer, a size and a capacity. For short text it stores the characters inside the object, so there is no heap allocation: SSO. Compiled: an empty string has capacity 15, "hello" was stored inside the object and a 40-character string was not.

FactWhy it matters
SSO limit is implementation-defined (15 in libstdc++, 22 in libc++)do not rely on the exact number
Capacity is the room before the next reallocation; size is the lengths.size() <= s.capacity()
Growth is geometric (usually doubling)compiled: appending 1000 characters one at a time reallocated 7 times
reserve(n) allocates once up frontcompiled: with reserve(1000) first, the buffer never moved
A reallocation invalidates pointers, references and iterators into the stringdo not keep s.c_str() across a modification
Moving a long string steals the pointer; moving a short one copies the inline bytesa move is cheap but never worse than a copy
Interview angle"What is SSO?" Short strings are stored in the string object, so no heap allocation and no pointer chase. It is why short-string copies are cheap and why string moves are not always pointer steals. On a hot path reserve and avoid building strings at all (Low-Latency C++).

String streams and files

TypeReads from / writes toHeader
std::istringstreamreads from a std::string<sstream>
std::ostringstreambuilds a std::string (.str())<sstream>
std::ifstream / ofstream / fstreama file<fstream>
  • Loop on the read, not on eof(): while (std::getline(f, line)) is right; while (!f.eof()) processes the last line twice.
  • Check the stream after opening: if (!f) { /* could not open */ }. A failed stream silently does nothing afterwards.
  • Stream state bits: good, eof, fail (a format error, such as reading text into an int), bad (a hard I/O error). clear() resets them.
  • Compiled: getline(csv, field, ',') split a three-field line, and a file of two lines read back as two lines.
  • Files are closed by the destructor, so a plain scope is the RAII way to flush and close.
  • std::endl flushes every time (slow). Use '\n'.

Try patterns (std::regex uses ECMAScript grammar, like this tester):

BackslashesWrite "\\d+" or a raw string R"(\d+)". POSIX classes like [[:alnum:]] work in std::regex but not in the tester.

Captures, replace and iterating matches

Parentheses make capture groups; std::smatch holds the whole match at 0, groups after.

Practical limits of std::regex
  • Constructing a regex is expensive: build once, not in a loop.
  • std::regex is slow; on hot paths use find/from_chars (or RE2, CTRE).
  • Nested quantifiers like (a+)+b can backtrack exponentially: no untrusted input.
  • Invalid pattern: std::regex_error.
Interview angleregex_match("hello world", regex("hello")) is false: it must cover the entire string. regex_search is true.

Time with std::chrono

Three ideas, in this order:

  • Duration: count plus unit; type-safe.
  • Time point: an instant since a clock's epoch.
  • Clock: the source of time points.

Interview cheat sheet

Answer aloud, then open.

When is a string_view dangerous?When it outlives the string it views: views of temporaries, of locals returned from a function, or of a string that is later modified or reallocated.
regex_match versus regex_search?regex_match must match the whole input. regex_search finds a match anywhere inside it.
How do you iterate over every match?std::sregex_iterator (or std::cregex_iterator for C strings) over the range, compared with a default-constructed end iterator.
Which clock for a timeout, and why?steady_clock, because it is monotonic and unaffected by changes to the system time.
Why can seconds = milliseconds not compile but milliseconds = seconds can?Converting to a coarser unit would truncate, so it requires an explicit duration_cast. Converting to a finer unit is lossless, so it is implicit.
What is the small string optimisation?Short strings (about 15 characters in libstdc++) are stored inside the std::string object, so no heap allocation happens and copying is cheap. Longer strings keep a pointer to a heap block. reserve avoids repeated reallocations when you know the size.
from_chars versus stoi?from_chars (C++17) returns an error code, never throws, never allocates and ignores the locale, so it suits hot paths and feed parsing; check that the end pointer reached the end of the token. stoi throws invalid_argument or out_of_range and is for ordinary code.
std::format versus streams versus printf?std::format (C++20) is type-safe, stateless and readable. Streams are extensible but keep state (std::hex sticks) and are verbose. printf has no type checking, so a wrong specifier is undefined behaviour.
Why is while (!f.eof()) the wrong way to read a file?eof becomes true only after a read has failed, so the loop body runs once more with a failed read. Loop on the read itself: while (std::getline(f, line)).
Output: what does this print? std::string s = "abc"; std::cout << s.find('z') == std::string::npos;It does not compile as intended: << binds tighter than ==, so it tries to compare the stream with npos. Parenthesise: std::cout << (s.find('z') == std::string::npos); prints 1.
