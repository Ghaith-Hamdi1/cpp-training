Strings, Regex and Time

Three standard-library areas that show up in real code and in interviews but are not covered by learncpp.com: owning and viewing text, pattern matching with <regex>, and measuring time with <chrono>.

std::string and std::string_view

std::string owns its characters: it allocates, copies and frees them. std::string_view (C++17) is a non-owning pointer plus a length. Passing a view costs two words and never allocates, but the view is only valid while the text it points at is alive.

Classic bug: dangling view A view must never outlive the string it looks at, and it is not guaranteed to be null-terminated, so do not hand sv.data() to a C API that expects a C string.
  • Small string optimisation (SSO): short strings (around 15 characters on common implementations) live inside the std::string object itself, with no heap allocation.
  • Use std::string_view for read-only function parameters. Keep std::string for anything you store.
  • s += a + b style concatenation can create temporaries; use append or reserve when building large strings in a loop.
Interview angle"const std::string& or std::string_view for a parameter?" View when you only read, because it accepts literals without constructing a temporary string. Reference when you need a real std::string (for example to call a function that needs null termination).

Regular expressions: the basics

A regular expression describes a set of strings. <regex> gives you three entry points, and the difference between the first two is a favourite question:

FunctionQuestion it answers
std::regex_matchDoes the whole string match the pattern?

std::regex_replaceReplace every match with a replacement string.

Try patterns yourself. std::regex uses the ECMAScript grammar by default, which is the same grammar this tester (the browser's own regex engine) uses for everything in the table above.

Backslashes in C++ stringsIn a normal string literal you must write "\\d+". A raw string literal avoids the doubling: std::regex re(R"(\d+)");. POSIX classes such as [[:alnum:]] work in std::regex but not in the browser tester.

Captures, replace and iterating matches

Parentheses make capture groups. After a successful search, std::smatch holds the whole match at index 0 and each group after it.

Practical limits of std::regex
  • Constructing a regex is expensive (it compiles the pattern). Build it once, not inside a loop.
  • std::regex is generally slow compared with hand-written parsing or libraries such as RE2 or CTRE. In hot paths or latency-sensitive embedded code, prefer simple find/from_chars parsing.
  • Patterns with nested quantifiers like (a+)+b can backtrack exponentially on bad input. Never feed untrusted input to a pattern you have not reasoned about.
  • An invalid pattern throws std::regex_error at construction.
Interview angle"Why does regex_match("hello world", std::regex("hello")) return false?" Because regex_match needs the pattern to cover the entire string. regex_search would return true.

Time with std::chrono

<chrono> is built from three ideas that are worth saying in this order in an interview:

  • Duration: an amount of time, a count plus a unit (seconds, milliseconds...). It is type-safe, so you cannot confuse seconds with milliseconds.
  • Time point: an instant, measured as a duration since a clock's epoch.
  • Clock: the source of time points.
ClockBehaviourUse it for
system_clockWall-clock time. Can jump (NTP, manual changes, daylight handling by the OS). Convertible to time_t.Timestamps, dates shown to people
steady_clockMonotonic: never goes backwards.Measuring elapsed time, timeouts
high_resolution_clockSmallest tick the implementation has. Often just an alias of one of the above.Rarely the right choice; prefer steady_clock
Use steady_clock for intervalsMeasuring elapsed time with system_clock can give negative or wildly wrong results if the system clock is adjusted while you measure. This matters for timeouts in real-time and embedded code.

Interview cheat sheet

Say each answer out loud, then open it.

When is a string_view dangerous?When it outlives the string it views: views of temporaries, of locals returned from a function, or of a string that is later modified or reallocated.
regex_match versus regex_search?regex_match must match the whole input. regex_search finds a match anywhere inside it.
How do you iterate over every match?std::sregex_iterator (or std::cregex_iterator for C strings) over the range, compared with a default-constructed end iterator.
Which clock for a timeout, and why?steady_clock, because it is monotonic and unaffected by changes to the system time.
Why can seconds = milliseconds not compile but milliseconds = seconds can?Converting to a coarser unit would truncate, so it requires an explicit duration_cast. Converting to a finer unit is lossless, so it is implicit.
Output: what does this print? std::string s = "abc"; std::cout << s.find('z') == std::string::npos;It does not compile as intended: << binds tighter than ==, so it tries to compare the stream with npos. Parenthesise: std::cout << (s.find('z') == std::string::npos); prints 1.
