unique_ptr: Exclusive Ownership

How unique_ptr makes ownership explicit: creating one, why it can be moved but not copied, how to pass and return it, deleters, arrays and polymorphism, and the usual mistakes. Builds on RAII and Move Semantics.

Ownership: who frees it?

Every object created with new must be freed exactly once. The owner is the code responsible for freeing it. With raw pointers the owner is a convention in someone's head; smart pointers write it into the type, so the compiler and the reader both know.

Creating a unique_ptr

A unique_ptr is a small object on the stack that holds the address of a heap object. When the unique_ptr is destroyed, its destructor deletes the heap object. That is RAII: you cannot forget to free it, even if the function returns early or throws.

Compiled with a Widget that prints from its constructor and destructor: it printed "built", then "in scope", then "destroyed" at the closing brace.

Key pointWhy make_unique? No naked new, the type is written once, and before C++17 f(unique_ptr<A>(new A), g()) could leak when g() threw between the two steps.

Move-only: handing over ownership

Two owners of one object would free it twice, so a unique_ptr cannot be copied. It can be moved: the object stays where it is and ownership passes to the new unique_ptr, which leaves the old one empty (nullptr).

OperationAllowed?
copy (auto c = a;)no: compile error
move (auto b = std::move(a);)yes: a becomes null
return from a functionyes: moved out automatically
store in a std::vectoryes, with push_back(std::move(p)) or push_back(make_unique<T>(...))

Cheat sheet

Answer aloud, then open.

What does unique_ptr guarantee?

Exactly one owner at a time. When the owner is destroyed it deletes the object, so you cannot forget to free it or free it twice by accident.

Why can a unique_ptr not be copied?

Two owners would delete the object twice. Ownership is transferred by moving instead, which leaves the source null.

How do you pass and return a unique_ptr?

Return it by value from a factory (it moves out). Take it by value, with std::move at the call, to take ownership. If the function only uses the object, take const T& or T* instead.

What is the overhead of unique_ptr?

None with the default deleter: the same size as a raw pointer and the same cost to use. A function-pointer deleter doubles the size; a stateless lambda adds nothing.

get(), release() and reset()?

get() returns the raw pointer and keeps ownership. release() gives up ownership and returns the pointer, so you must delete it. reset() destroys the object now.
