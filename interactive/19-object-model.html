Multiple inheritance and object layout

A class may have several bases. The sensible use is several pure interfaces (abstract classes with no data), as in Java:

  • The object is the bases laid out one after another, then the derived members. Compiled: sizeof(File) is 24 bytes (two vptrs and an int).
  • Converting File* to the second base adjusts the pointer value (static_cast and implicit conversion do it for you). That is why you must not cast with reinterpret_cast or a C cast.
  • Both bases are polymorphic, so delete through either needs a virtual destructor.
  • Name clashes: if both bases have a member f, calling obj.f() is ambiguous. Qualify it (obj.Reader::f()) or override it in the derived class.
  • Multiple inheritance of implementation (bases with data) is where trouble starts: the diamond.

RTTI: typeid and dynamic_cast

RTTI (run-time type information) lets you ask for the dynamic type of an object behind a base pointer. It works only for polymorphic classes (at least one virtual function), because the type information lives next to the vtable.

Private inheritance versus composition

KindMeaningConverts to base outside?
public inheritanceis-a: usable wherever a Base isyes

protected inheritancelike private, but derived classes of the derived class see the baseno
  • Prefer composition (a member Engine engine_;): it is simpler and does not expose the base's virtual functions to accidental overriding. Use private inheritance only to override a virtual function of the base, access a protected member, or get the empty base optimisation (an empty base takes no space; a member takes at least 1 byte).
  • Never inherit publicly just to reuse code: if it is not is-a, it breaks the Liskov substitution principle (SOLID).

explicit, conversion operators and copy-and-swap

  • Mark single-argument constructors explicit unless an implicit conversion is clearly wanted (compiled: double converts to Meters but not to Feet).
  • explicit operator bool is the safe way to say "valid": it works in if, while, && and !, but not in arithmetic or in comparisons with other types (the old "safe bool idiom" is obsolete). The standard streams and std::optional use it.
  • A non-explicit operator int() lets your class take part in arithmetic and overload resolution in ways you did not plan.

Copy-and-swap

  • Strong exception guarantee: if the copy throws, it happens before *this is touched.
  • Self-assignment safe without an if (this != &o) check (compiled: b1 = b1 worked).
  • One operator serves copy and move assignment (Move Semantics). Cost: a move-assignment written by hand can be a little faster.

Interview cheat sheet

Say each answer aloud, then open it.

What is the diamond problem and how is it solved?

A class inherits the same base through two paths, so the base's members are duplicated and access is ambiguous. Virtual inheritance (class Left : virtual Base) makes all paths share one base subobject, which the most derived class constructs first. It adds memory and indirection, so prefer interfaces without data or composition.

Why do Reader* and Writer* to the same File hold different addresses?

With multiple inheritance the object contains each base subobject at its own offset, each with its own vptr. Converting to the second base adjusts the pointer to that subobject, which is why C casts and reinterpret_cast are wrong here.

What does dynamic_cast need and what does it cost?

A polymorphic class (a virtual function) because it reads the type information next to the vtable. It checks the real type at run time: null for pointers, std::bad_cast for references. It is slower than a virtual call, so avoid it on hot paths; repeated use suggests a missing virtual function or a Visitor.

typeid on a polymorphic versus non-polymorphic type?

On a polymorphic object typeid(*p) gives the dynamic type. On a type with no virtual function it gives the static type, known at compile time. type_info::name() is implementation-defined and only for diagnostics.

When is private inheritance appropriate?

For "implemented in terms of": to override a virtual function of the base, access its protected members, or use the empty base optimisation. Otherwise prefer composition. It does not allow conversion to the base outside the class.

What does explicit do on a constructor and on operator bool?

On a constructor it forbids implicit conversions from the argument type (Feet f = 3.0 fails). On operator bool it allows the conversion only in contexts such as if and while, not in arithmetic. Mark single-argument constructors explicit by default.

What is copy-and-swap?

Write the copy constructor and a non-throwing swap, then implement operator=(T other) by value that swaps with the parameter. The copy happens before *this is modified, giving the strong exception guarantee and safe self-assignment with one function.
