Perfect Forwarding

Passing arguments through a wrapper without changing their value category: why std::forward is needed, how reference collapsing makes it work, and where it fails. Assumes Sink Parameters and Move Traps and Function Templates.

Why a wrapper loses the category

Suppose you write a wrapper that passes its arguments on to another function (make_unique, emplace_back, a logging wrapper). The caller may pass an lvalue or an rvalue, and the target should copy or move accordingly. But inside the wrapper, the parameter has a name, so it is an lvalue, and the target would always copy.

std::forward restores it

std::forward<T>(a) casts a back to what the caller passed: an rvalue reference if the argument was an rvalue, an lvalue reference if it was an lvalue. It works because the parameter is a forwarding reference: T&& where T is deduced (see Function Templates).

Reference collapsing

Why does T&& sometimes mean an lvalue reference? Because C++ does not allow a reference to a reference, but templates can create one by substitution. The rule for resolving it is reference collapsing: if either side is an lvalue reference, the result is an lvalue reference.

ArgumentDeduced TParameter T&& becomes
an lvalue s of type stringstring&string&
an rvalue string("x")stringstring&&

std::forward<T> uses exactly that: with T = string& it returns string& (an lvalue), with T = string it returns string&&.

Where forwarding fails

Perfect forwarding is not perfect for every argument. Deduction fails or picks the wrong type in a few cases.

ArgumentWhy forwarding fails
a braced list {1, 2}a braced list has no type, so T cannot be deduced; name the type or pass a std::initializer_list
0 or NULL as a null pointerdeduced as int, which does not convert to a pointer; use nullptr
the name of an overloaded or template functionthe compiler cannot choose which overload to deduce; cast to the exact function pointer type or use a lambda
a bit-fielda non-const reference cannot bind to a bit-field; copy it into a local first
a static const data member with no definitionbinding a reference odr-uses it and the linker may fail

These are the cases Effective Modern C++ Item 30 lists. In practice the first two cause most surprises.

Forwarding in practice

Forwarding is how the standard library builds generic wrappers: make_unique, make_shared, emplace_back, std::thread, std::function and std::invoke all forward their arguments. Here is the shape of a wrapper that calls anything:

PartWhy
Args&&...a pack of forwarding references: each argument binds to whatever it was
std::forward<Args>(args)...expands once per argument, restoring each one's category
decltype(auto) returnreturns exactly what the callee returns, including references
  • If a wrapper passes an argument to two calls, forward only the last one.
  • A constrained wrapper (a concept or enable_if) avoids hijacking copy construction: an unconstrained T&& constructor beats the copy constructor for non-const lvalues (Effective Modern C++ Item 26).

Cheat sheet

Answer aloud, then open.

What is perfect forwarding, and why do we need it?

Passing arguments through a wrapper to another function without changing their value category or constness, so the callee can still choose copy vs move correctly. Without it you would need an overload per combination of lvalue/rvalue/const for every parameter.

What is the difference between std::move and std::forward?

std::move always casts to an rvalue. std::forward<T> casts to an rvalue only if the argument that was passed was an rvalue, and keeps an lvalue otherwise. Use forward only on a forwarding reference, once.

What is reference collapsing?

The rule that resolves a reference to a reference created by templates: T& &&, T&& & and T& & all become T&; only T&& && stays T&&. It is why a forwarding reference can bind to both lvalues and rvalues.

Is every T&& a forwarding reference?

No. It must be T&& where T is deduced for that very function template (or auto&&). std::vector<T>&&, a const T&& and the T&& of a class template's member function are plain rvalue references.
