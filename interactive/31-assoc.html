Maps, Sets and Hashing

Lookup by key: map and set are sorted trees, the unordered containers are hash tables. operator[] versus find, try_emplace, multimap, custom comparators and hashes, and pair and tuple. Assumes STL Containers.

operator[] on a missing key inserts it with a default-constructed value. To only check, use m.find("x"), m.count("x") or m.contains("x") (C++20).

  • try_emplace is the right call for "insert if absent" when building the value is expensive or the argument is move-only.

Custom keys: comparators and hashes

A map/set needs an ordering; an unordered_map/unordered_set needs a hash and equality. For your own key types, you provide them.

ContainerKey must provideRule
map, seta strict weak ordering (operator< or a comparator)irreflexive and transitive; equivalence means "neither is less". <= is not valid: undefined behaviour
unordered_map, unordered_seta hash and operator==equal keys must have equal hashes; a poor hash makes every lookup O(n)
  • Transparent comparators: std::map<std::string, int, std::less<>> lets find take a string_view or const char* without building a temporary std::string (compiled: it found "apple" from a string_view). C++20 adds the same for unordered containers.
  • Never change a key while it is in the container: its position or bucket would be wrong. Keys are const for that reason.
  • Hash quality: combine all fields; avoid returning just one field. std::hash for int is the identity in libstdc++, which is fine.
  • A rehash (growth beyond max_load_factor) invalidates iterators; reserve(n) up front avoids it, and avoids the allocations on a hot path.
  • Ordered or hashed? Ordered when you need sorted iteration or range queries (lower_bound); hashed for plain lookup. For a few dozen keys a sorted vector and binary search often beats both.
Key point"How do you use your own type as a key in unordered_map?" Provide operator== and a hash functor (or specialise std::hash), combining all members, and make sure equal objects hash equally.

pair, tuple and structured bindings

std::pair<A, B> holds two values, std::tuple<A, B, C...> any number. Structured bindings (C++17) unpack them into named variables.

  • A pair or tuple has no names: .first and std::get<2> say nothing about meaning. For a result that leaves a function and is used in more than one place, a small named struct reads better.
  • Comparison is built in and lexicographic: pairs and tuples compare element by element, so they work as map keys and in std::sort.
  • std::tie(a, b) = f(); assigns into existing variables; std::ignore skips one.
  • Structured bindings also unpack plain structs and arrays: auto [x, y] = point;. They are copies unless you write auto& or const auto&.

Cheat sheet

Answer aloud, then open.

How do you use your own type as a key in unordered_map, and in map?

unordered_map: provide operator== and a hash functor (or specialise std::hash) that combines all members; equal objects must hash equally. map: provide a strict weak ordering (operator< or a comparator type). Never <=, and never modify a key while it is stored.

Why use try_emplace instead of emplace or insert?

If the key exists, try_emplace does nothing and does not touch its arguments, so a moved-in value is not lost. emplace and insert may already have built or moved from the value. It is the right call for "insert if absent" with expensive or move-only values.

map vs unordered_map?

map: balanced tree, sorted iteration, O(log n), needs operator<, supports range queries. unordered_map: hash table, average O(1) (worst O(n) with many collisions), no order, needs a hash and ==. Choose unordered_map for plain lookups and map when you need order.

What is a hash collision and how is it handled?

Two different keys hash to the same bucket. The standard library's unordered containers resolve it with chaining (a bucket holds a list of entries), so lookups in a heavily colliding bucket degrade toward O(n). A good hash function and a sensible load factor (rehash, reserve) keep it near O(1).

Why does m[key] on a missing key matter?

operator[] inserts a default-constructed value and returns a reference to it, so reading a missing key grows the map. To only look, use find, count or contains (C++20); at() throws instead of inserting.

How do you return several values from a function?

A std::pair or std::tuple read with structured bindings (auto [lo, hi] = minmax(v)) when the values are used right away; a small named struct when they travel further and deserve names.
