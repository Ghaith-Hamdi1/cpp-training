In a type, && does not mean “and”.

It is a new kind of reference.

int&  a = x;
int&& b = 5;

The second one is an rvalue reference.

Added in C++11. It is what makes move semantics possible.

Why: copy or steal

std::vector<int> b = a;               // copy
std::vector<int> b = std::move(a);   // move
Copy

New block, new ints.

Move

Same block, new owner.

A move copies one pointer, not the elements.

C++ IN MOTION · #155 / 6

std::move moves nothing

std::string a = "hello";
std::string b = std::move(a);

It is only a cast: “treat a as an rvalue”.

The move itself happens in the move constructor of std::string.

After it, a is moved-from.

  • still valid, contents unspecified
  • only destroy it or assign to it
