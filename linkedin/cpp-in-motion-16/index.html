The const after a member function's parentheses is a promise.

It will not change the object.

C++ IN MOTION · #162 / 6

What it means

struct Counter {
    int n = 0;
    int get() const { return n; }    // ok
    int bad() const { ++n; return n; } // error
};

Inside, this is a const Counter*.

So the members are read-only there, and the compiler rejects any write.

C++ IN MOTION · #163 / 6

Who can call it

const Counter c;
c.get();    // ok
c.inc();    // error: inc is not const

int f(const Counter& c) {
    return c.get();
}

A const object can only call const functions.

A missing const on a getter makes it unusable through const&, which is how most parameters are passed.

C++ IN MOTION · #164 / 6

Two versions of one function

struct Vec {
    int& at(int i);
    const int& at(int i) const;
};

Vec v;        v.at(0) = 5;    // first
const Vec c;  int x = c.at(2);  // second

const counts as part of the signature.

The standard containers do exactly this. I ran it and each call picked the version I expected.

C++ IN MOTION · #165 / 6

The escape hatch: mutable

class Account {
    mutable std::mutex m_;
    int balance_ = 0;
public:
    int balance() const {
        std::lock_guard g(m_);
        return balance_;
    }
};

For members that are not part of the visible state: a lock, a cache, a counter.

Without mutable the lock does not compile in a const function.
