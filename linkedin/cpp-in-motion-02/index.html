Two kinds of copy

You writeWhat runsIts job
Numbers b = a;copy constructorbuild a new object from a
b = a;copy assignmentoverwrite an existing b with a

If you write neither, the compiler writes both for you. It copies every member, one by one.

For an int or a std::string member, that is exactly right.

For a raw pointer it copies the address, not what it points to.

The Rule of Three

If you write one of these, you almost certainly need all three.

You writeBecause
~Numbers()
destructor		the class owns a resource and must release it
Numbers(const Numbers&)
copy constructor		a copy must not share the resource
operator=(const Numbers&)
copy assignment		the same for b = a: copy into b, never share

No compiler enforces it. It is a design rule.

C++ IN MOTION · #26 / 7

The fix: copy the ints

Numbers(const Numbers& o)
    : data(new int[3]) {
    std::copy_n(o.data, 3, data);
}

New block, same values.

a and b now own separate blocks.

operator= needs the same fix. Together with the destructor, that is the Rule of Three.
