Copy a Derived into a Base and the Derived part is cut off.

That is object slicing.

Derived d;
Base b = d;   // d's y is gone

It compiles without a single warning.

C++ IN MOTION · #113 / 6

Even the virtual call changes

Derived d;
Base b = d;
b.print();

Prints "Base", not "Derived".

b is a real Base object. Its hidden vtable pointer was built for Base.

A virtual call only follows the real type if you go through a pointer or reference to the original object.

C++ IN MOTION · #114 / 6

Where it hides

void f(Base b);                // slices

std::vector<Base> v;
v.push_back(Derived());         // slices

catch (Base e) { }                // slices

Passing by value, storing in a container, catching by value.

All three sliced in my test, and the virtual call then printed "Base".

C++ IN MOTION · #115 / 6

The fixes

void f(const Base& b);

std::vector<std::unique_ptr<Base>> v;

catch (const Base& e) { }

Pass by reference, store pointers, catch by reference.

Or make the copy impossible: Base(const Base&) = delete; turns the slice into a compile error. I checked.
